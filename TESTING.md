## 2. Test-driven development scope

Written test-first (red → green → refactor): replay engine (including M1's confirmation-replay executor), locator generation and resolution, deterministic visual checks, text matching, expectation-coverage compiler rules, `side_effect` inference, heal-verdict schema and heal-patch validator (target locators and non-side-effect steps only), step intents and lease fencing, RLS policies and `set_config` context, token/OIDC/webhook verification, domain verification, API-key hashing, secret redaction and origin binding, egress enforcement (including the IP policy and document-origin checks), runner startup hygiene.

## 3. Tenant isolation tests

- A registry lists every tenant table and tenant-scoped endpoint. **CI fails if a new table/endpoint is not registered** (introspection compares `information_schema` and FastAPI routes to the registry).
- For each entry: seed orgs A and B; as A, attempt select/insert/update/delete of B's rows at the DB layer (as `app_user` with `app.org_id=A`) and via the API. Expect zero rows / `404` (never `403`, to avoid leaking existence).
- Unset-context test: queries with no `app.org_id` return zero rows. Unmapped Clerk `o.id` is rejected before any query.
- Definer-function test: pre-tenant lookup functions return only identifiers, never tenant rows.
- Run-token test: a token for run X cannot read or write run Y, even in the same org; an expired lease's token is rejected.

## 4. Agent tests without spending money

- **Cassettes:** LLM calls recorded once against real providers, played back in CI. Keyed by prompt hash (VCR.py's matcher compares a sha256 of the canonical request body, plus method and URL); a changed prompt fails loudly and must be re-recorded deliberately. The four successful cases (`coverage_plan`, `tools`, `structured_output`, `plain_with_effort`) now contain real Anthropic responses with request IDs. ADR-0024's live-recording amendment gives the source SHA, commands and measured costs.
  - *Record one named case at a time.* Load `ANTHROPIC_API_KEY` from an ignored file, never type its value. From the worktree root:
    ```bash
    set -a; . "$PWD/.scratch/provider.env"; set +a
    uv run python -m packages.runner.tests.record_cassettes coverage_plan "$PWD/.scratch/captures/<round>/001"
    ```
    Choose a new ignored attempt directory for every call, inside one round directory for a plan case (below). The other case names are `tools`, `structured_output` and `plain_with_effort`. Inspect the receipt before the next call; stop on a provider limit, an unpriced response or an ambiguous failure. The recorder clears endpoint overrides, builds the existing router before LangChain runs, and uses the existing example requests and configured model. Only `plain_with_effort` sets the existing example's `high` effort. No prompt, schema, output bound or price is overridden, and only `explore_fixture` and the plan cases turn the SDK's retries off (below). For the recording's lifecycle every Python logger is off and Playwright's debug switches (`DEBUGP`, `DEBUG`, `DEBUG_FILE`, `PWDEBUG`, `PWDEBUGIMPL`) are cleared, so neither `ANTHROPIC_LOG` nor Playwright can print or write what a recording sends or types (LAB_NOTES, 2026-10-18); both are restored after.
  - *Costs before acceptance.* The private attempt retains `intent.json` (case, source SHA, start time, role, provider, model and effort), `responses.jsonl` (request IDs, status, available usage and observed response intervals), `request-hashes.json`, the sanitized cassette, and `receipt.json` (outcome, finish time and CostRecords). Extra SDK responses with usage use the existing `cost_record` and resolved price map; their latency is the measured interval since the preceding response or capture start, including SDK backoff and overhead. Missing or malformed usage is explicitly unpriced. A transport failure with no response is marked `no_response`, not assigned a zero bill. Preserve failed attempts and investigate before rerunning.
  - *The five pilot plans:* `plan_login`, `plan_read-article`, `plan_post-comment`, `plan_favorite-article` and `plan_publish-article` are recorded from the committed pilot specs (the recorder copies each spec and the project config, so a recording reads what it hashes), with the named recorder, at source commit f9f17b0 (4844fe7 when recorded, before the rebase onto main); `plan_post-comment` was re-recorded at 417d033 and `plan_publish-article` at 08faf54 (ADR-0024's #161 amendment). #55's round re-recorded all five and `coverage_plan` on 2026-10-22: `plan_favorite-article` at 6738975, `coverage_plan`, `plan_login` and `plan_read-article` at d3493f3, and `plan_post-comment` and `plan_publish-article` at 71a9109 (ADR-0024's #55 receipts table). Re-record a pilot only for a changed prompt or spec, never to change wording, and read `ADRs/0024-explore-runs.md` before paying: three prompt rounds and #161's targeted re-records were already spent.

A round is one ignored directory, the only one for the pre-approval, and each attempt a new directory in it (the spend ledger reads only that directory): `uv run python -m packages.runner.tests.record_cassettes explore_fixture "$PWD/.scratch/captures/<round>/001"`, then `002` and `003`. For this case alone the SDK's retries are off, and every request first reserves its worst case against the recording's spend bound, a run's limit and the round's, less what the round's earlier receipts spent; one that would cross either is refused unsent. A response billed more input tokens than its request reserved stops the round. Promotion needs explore's exit 0 with a confirmed script and one priced, identified response for each line of the run's own `costs.jsonl`. A withheld response of either class reached the SDK unread, so the recorder then also removes the attempt's cassette, `qa/.aqa` and `qa/.compiled`; one it can't remove is a `scrub` finalization failure, and the operator removes it, unread, before anything reads the attempt. The receipt adds `withheld`, `scrubbed`, `explore` (exit code, outcome, publication) and `spend`; success needs the recorder's exit 0 as well as an `accepted` receipt. ADR-0024's #53 P21a amendment holds the bound, the receipt fields and a live round's stop rules; `test_record_explore_cassette.py` tests them against a local stand-in with a fake key. The cassette was recorded once, within `ROUND_USD` (ADR-0024's #53 P21b receipts). `test_explore_cassette.py` replays it offline through `aqa explore` with the real adapter, to a confirmed script, and reads its requests: no forced tool choice, and each turn one user message of two blocks under the navigator's instructions.
  - *Sanitation and promotion.* The existing VCR filter keeps only request `content-type` and `anthropic-version`, response `content-type` and `request-id`, decoded response text, and the canonical API address. The recorder checks raw response text, decoded wire JSON keys and values, the adapter's assembled text, and the structured parser's decoded JSON (including fenced and partial JSON) for the active key and the policy guard's credential formats. A match withholds the response before saving it; uninspectable content is withheld too. Validated usage is retained first, so malformed content can still be priced. A case must pass its existing parsing/plan checks, carry a request ID on every response, and have exactly one priced response, or, for a plan case whose first plan couldn't be used, two `ok` ones (`make_plan`'s one retry, ADR-0024's #161 amendment), before the candidate replaces the library cassette. The attempt copy remains. Other multi-response attempts, such as a refusal and its fallback, stay private. `test_record_cassettes.py` exercises these paths with disposable local servers and fake keys.
  - *Failure finalization.* The recorder gives its own VCR instance a deferred persister: VCR releases transport patches before the cassette is serialized and written. Receipt writing is attempted even after SDK, cassette or request-hash failure. Fixed `primary_failure` and `finalization_failures` categories distinguish call failures from evidence failures; returned records remain separate from the once-counted observed costs, and ambiguous associations fail acceptance. The separate `first_interrupt` category retains the earliest interrupt from the call, capture finalization or promotion. It keeps its class with a safe payload: empty `KeyboardInterrupt`/`CancelledError`, or `SystemExit(1)`, even if a later write fails. A successful call followed by an interrupt leaves `primary_failure` unset. The exception exposes safe receipt-attempt/completion flags when no receipt could be saved; it never displays the original exception chain.
  - *Warnings and replacement.* Warnings are errors only inside the recording lifecycle; the caller's warning policy is restored afterward. This prevents SDK serialization warnings from printing response values under ordinary CLI settings. An `accepted` receipt certifies capture validation and accounting, not library replacement: `record` returns successfully only after replacement succeeds. A failed promotion keeps the accepted capture evidence, reports `promotion_failed` in the outgoing safe diagnostic and exits nonzero. Preserve and inspect that attempt before any deliberate retry. A disk failure can prevent a complete receipt; process death, exhausted memory or repeated interruption can prevent finalization. A crash immediately after replacement may leave an ambiguous result. None is evidence of zero spend or permission to retry automatically.
  - *Six failure cassettes remain hand-written by design.* `refusal`, `structured_invalid`, `structured_truncated`, `tools_truncated`, `no_usage` and `refusal_then_fallback` represent cases a live API will not reliably produce on demand. Their `BY DESIGN` headers and asserted values stay intact. `AQA_RECORD_CASSETTES=1` remains supported by the lower-level fixture, including its by-design guard, but it does not provide the recorder's cost ledger or post-response acceptance check. Use the named recorder for paid replacement captures. `test_cassettes.py` tests that fixture against a local stand-in.
  - *Replay spends nothing.* Leave `AQA_RECORD_CASSETTES` unset. The fixture supplies a fake key and refuses unmatched requests; tests marked `replay_only=True` never record. For an explicit check without a provider credential:
    ```bash
    env -u ANTHROPIC_API_KEY -u AQA_RECORD_CASSETTES uv run pytest packages/runner/tests/test_anthropic_client.py packages/runner/tests/test_model_router.py packages/runner/tests/test_coverage_plan.py packages/runner/tests/test_record_cassettes.py
    ```
  - *Editing a hand-written cassette.* When a request changes on purpose, a by-design cassette no longer matches and can't be re-recorded: the failure prints the request body that was sent, so replace the cassette's `request.body` with it and keep the response. A test that isn't about the API's answers (tracing, the fixture's own) passes `replay_only=True` and never records.
  - *Why the keys stay stable:* the navigator's prompts depend only on graph state, and the coverage plan's prompt depends only on the spec (ADR-0024). The plan's request is the static instructions, then the spec's frontmatter as validated, as JSON, without `tags`, the account or the reset hook, with the start URL and each probe cut at its query (`aqa_runner.coverage_plan.plan_request`): never the spec's path, its Markdown body, the start origin or the environment. `test_the_plan_cassette_replays_for_the_spec_run_from_anywhere` replays one cassette for the same spec from two spec roots and start origins.
  - *What else is in the plan's request:* the plan models' docstrings reach the model as the response format's descriptions (`aqa_core.coverage_plan`), so editing one, or the instructions, changes the request. Re-record the real `coverage_plan` case; do not pair an old provider answer with an edited request.
  - *Bounds:* every request asks for at most 4096 output tokens, and each try waits at most 120 s for its answer, with the SDK's two retries after it (none while the recorder records `explore_fixture` or a plan case), as the adapter states them (`aqa_runner.anthropic_client`, LAB_NOTES 2026-10-02). `test_every_request_in_every_cassette_asks_for_the_output_bound` holds every cassette to the first, and `test_a_request_that_gets_no_answer_times_out` shows the second against a server that never answers.
  - *Wire requests:* per provider, cassette tests also check what each adapter actually sends. For example, no request forces a tool choice (ADR-0007 amendment). Anthropic's are in `test_anthropic_client.py`, with a control that shows langchain-anthropic's default structured output would force one. The same file shows that an ambient `LANGSMITH_GATEWAY` can't take a call away from Anthropic's own endpoint, or put a LangSmith key on it.
  - *Tracing:* an ambient `LANGSMITH_TRACING`, `LANGCHAIN_TRACING_V2` or `LANGCHAIN_TRACING` exports nothing once a router exists; `test_tracing.py` sets each against a local stand-in for LangSmith's API, and shows that without the guard the run does reach it.
  - *Pages that change between runs:* a page whose content differs from run to run, such as one with a random slug, can't be replayed from a cassette. The pilot's full explores are live, recorded runs whose evidence cites the SHA.

## 5. Benchmark

Location: `bench/`. Two open-source apps with **60 planted bugs** behind feature flags across six categories (functional, visual/layout, backend 5xx, JS error, broken flow, data display) and **20 benign UI changes** (moved/restyled/relabeled elements, reordered nav — every expectation still holds).

**Flags and ground truth (ADR-0022):** each case is one opaque flag, set through `BENCH_FLAGS` when the app's containers are recreated (which also reseeds the database). Specs reach app state only through the app's `/test-api/*` reset hook and narrow read-only probes. Ground truth lives only in `bench/manifest.v1.json`, keyed by case ID.

**Browser settings:** every run pins its browser settings (time zone UTC, locale en-US, viewport 1280×800), and the compiled script records the settings it was explored under (ADR-0025). Benchmark runs use the defaults, as `bench/harness/toggle_checks.py` does. Apps render dates in the viewer's time zone. Conduit's seeded article times (10:00 UTC) show their seeded dates only between UTC−10 and UTC+13, so a replay in another zone would fail the clean app.

**Pilot first (M0):** one app, ~5 bugs and 2 benign changes, development-only — enough to validate the compiler, the expectation-coverage rules, and the heal contract before investing in the full benchmark. Pilot cases join the dev split. The full benchmark is written and its split frozen at the start of M3, before any tuning on it.

### Pilot acceptance (M1 exit)

`bench/harness/pilot.py` is the acceptance layer's command (§1). bench/README.md has its usage and exit codes, and ADR-0023 its design.

- **What it proves.** The clean app's repeats are equal, eligible passes. Each dev case's scored pairs match the manifest exactly. Each benign pair's fresh, patched attempt passes, which the report calls `accepted`, and its attempts list each broken binding and the locator that resolved each step and check. Pairs the manifest omits are reported unscored, so a generic exit 0 isn't the M1 exit: the read-article proof and #58's run of the five pilot specs, which must accept the scored benign pairs, complete it.
- **Running it.**
  - Run it from a clean commit with `--repeat 3` and a new `--out` under `.scratch/`.
  - Root first reserves the app's Compose project and port, because the command recreates the stack for every switch.
  - The command needs Docker, so it doesn't run in CI. Its tests do: fakes for Docker and the replay, plus three real-Chromium runs against a loopback page.
- **Evidence.**
  - **Citing.** A pull request cites `report.json` and the command line. A report is citable only when it is `diagnostic: false` and `source_unchanged: true`, and the commit it names is the one cited.
  - **Private records.** The run records under `.aqa/runs/` stay private and are never attached, because they can hold page text. #50 owns sanitizing them.
  - **When release is forbidden.** If the report says `reservation_release: forbidden`, or the run holds after `cleanup-incomplete.json`, root reconciles the stack before releasing it. The run makes no model call and never switches a test-split case.
- **The read-article proof.** `bench/harness/pilot_read_article.py` judges a run of the hand-written read-article script in `bench/harness/fixtures/` (bench/README.md has its exit codes, ADR-0023 its design). `bench/harness/test_read_article.py` covers what needs no Docker:
  - **The fixture.** Its spec, plan and subject-contract hashes are the owning functions' values now, its targets carry exactly the config's row contracts, and admission takes it and a locator-only patch of it but refuses any origin beyond the stack's. Conduit's template has one `div.comment-list`, around the comment loop alone.
  - **Each check establishes its claim.** The real adapter replays it against loopback versions of the signed-out article page, with no model client constructed. Each wrong title, author, date, body, tag, comment or prompt fails exactly its check, and the comment's quote placed only in the prompt, the body, the footer, an error or the signed-in form fails the list's. The form replaces the prompt, so it fails the prompt's too. With no comments the list's check fails; with two, either may hold the quote. A missing or doubled `div.comment-list` leaves it `binding_unresolved`.
  - **The proof.** Reports come from `pilot.py` itself, Docker and the replay faked. A changed outcome, an unscored failure under a generic exit 0, a missing or extra pair or attempt, a reused run ID, a changed field, a check resolved by any locator but its first, a stale source or hash, and an added dev case that fails all exit 1. An unreadable report, a plan that doesn't fit the spec and a root with no commit exit 2 with a fixed message. The input and any existing output keep their bytes.
  - **On the real app.** Rebuild the frontend image (`flags.py` doesn't), run `pilot.py conduit --spec read-article --compiled-dir bench/harness/fixtures --repeat 3`, then the proof on its `report.json`. A pull request cites both command lines, the proof and the commit, and, for the wrapper, the article's before and after screenshots at 390 px and 1440 px (AGENTS.md §7). ### Splits (frozen before any tuning)
| Split | Bugs | Benign changes | Use |
|---|---|---|---|
| **dev** | 20 | 6 | Building and tuning prompts, routing, heuristics; PR smoke subset |
| **test (frozen)** | 40 | 14 | Release numbers only; never run in CI, never used for tuning |

- Related bugs (same code path or same "family") are assigned to the same split so the test set isn't leaked through near-duplicates.
- The split manifest is committed with a hash before M1: `bench/manifest.v1.split.sha256` covers each case's split and family, and a unit test recomputes it (ADR-0022). Once test results influence a design decision, that test set is **burned**: the next release uses a freshly written test set (v2), and the README says which version produced its numbers.

### Procedure
1. Explore each spec on the clean app → compiled scripts committed to `bench/apps/<app>/qa/.compiled/`.
2. For each bug flag: enable, run `aqa run` (strict mode), record verdicts. Ground truth: "expectation violated in spec S".
3. For each benign change: enable, run, record. Ground truth: `drift_consistent`.
4. Flake measurement (clean apps): **30 specs × 20 repeated replays = 600 replays**. Replays of the same spec are not independent, so two quantities are reported (see table).
5. Compute metrics with CIs, per category, on the relevant split.

### Metrics, targets, and statistical conventions
| Metric | Target | Reported as |
|---|---|---|
| Planted-bug detection rate | ≥ 85% | Point + two-sided 95% Wilson CI, per category (test split: 40 bugs) |
| False-positive rate (findings filed on clean runs) | ≤ 5% | Point + two-sided 95% Wilson CI |
| Heal classification accuracy (benign set → `drift_consistent`) | ≥ 90% | Point + two-sided 95% Wilson CI (test split: 14 changes — the interval will be wide, and we say so) |
| Flake rate | Observed < 1% of replays | (a) **Pooled replay rate** with a one-sided exact 95% upper bound computed *under an explicitly stated assumption* that replays are conditionally independent (0/600 → ≤ 0.50% under that assumption); (b) **per-spec flake incidence** — the fraction of specs with ≥ 1 flake in 20 repeats — with a one-sided exact bound over 30 specs as the assumption-free unit (0/30 → ≤ 9.5%). Both are published; (b) is the conservative claim. No bootstrap bound is reported for all-zero data (it's degenerate) |
| LLM cost per strict replay | $0 | Exact (no model client constructed) |
| Median LLM cost per heal | < $0.05 | Median + bootstrap CI |
| 10-step replay time | < 30 s | Measured locally at M3 and on a hosted MicroVM at M6, cold and back to back — reported separately (ADR-0032: at risk on hosted) |

Every interval states its method and sidedness. With small splits, intervals are wide — publishing them honestly is the point.

Outputs: `bench/results/<date>-<sha>-<split>.json` + generated Markdown table. **README numbers are copied only from a test-split results file whose SHA is cited next to them.** Ablations (dev split): perception mode (tree-only / vision-only / hybrid) and per-role model comparisons; `verified`-mode results reported as a separate table with its own cost.

PR smoke: 8 dev-split cases (≈ 2 min, recorded cassettes). Nightly: full dev split with live models on a budget-capped key.

## 6. Flake policy

- A replay that fails then passes on retry is recorded as **flaky**, not passed. Flakes are tracked per spec and surfaced in the dashboard.
- No blanket retries in CI. Any retry is explicit, counted, and reported.
- **Explore applies the same rule** (ADR-0024). If a confirmation replay fails and a later one passes with the identical compiled script, the spec is flaky: explore writes nothing and reports why.

## 7. Dashboard quality

- Every screen has Playwright tests for its loading/empty/error/permission states.
- Visual snapshots at 390px and 1440px in dark and light themes; UI PRs attach before/after screenshots (project acceptance rule).
- Axe accessibility checks on core flows (no serious/critical violations).
