# ADR-0033: M1 saves no screenshots; bound-field masking moves to M2

- Status: Accepted (amended 2026-10-27: the capture and the record's binary writer exist, ADR-0034; 2026-10-28: the OCR check, ADR-0035; 2026-11-14: the paths that save screenshots, #251; 2026-11-14: the "before" screenshot, opt-in, #314)
- Date: 2026-10-08

## Context
ADR-0026's Evidence decision saves a screenshot after each step and masks every secret-bearing field in it, and #50's second criterion asks for that: "Every saved screenshot masks the secret-bearing field." Three facts shape what M1 can deliver:
- **Playwright's mask is an overlay the page owns.** In a measured probe, a page hid it with one CSS rule and removed it with a MutationObserver. Both times the saved PNG showed the bound field's fake value in full, while the field's identity, box and frame stayed the same before and after the capture (LAB_NOTES, 2026-10-07). No check made before or after the capture can see an overlay the page hid during it.
- **Most pilot runs bind a secret.** Four of the five Conduit pilot specs bind `TEST_PASSWORD` (`bench/apps/conduit/qa/`: login, favorite-article, post-comment and publish-article; read-article doesn't).
- **M1 has other evidence and no model that looks at pixels.** Each kept step already saves a scanned accessibility snapshot and metadata-only console and network logs (ADR-0026's #50 B amendment), and M1's navigator reads the accessibility tree only (ADR-0024).

## Options
1. **Masked screenshots:** Playwright's `mask`, with the field's identity, box and frame checked before and after the capture. Both measured attacks pass every one of those checks.
2. **Screenshots only where nothing is bound:** capture only in a run that binds no secret and shows one main document, and withhold every other. That saves none for four of the five pilot specs, and still adds a capture entry, a binary writer and lifecycle tests (planned at 315 to 385 changed lines) for an image of the simplest pages, which can still show sensitive content the run never bound.
3. **No screenshots in M1:** bound-field masking moves to M2, beside the OCR checks.

## Decision
Option 3 (the maintainer, 2026-10-08). M1 has no screenshot capture and no binary writer; a step's evidence is its scanned snapshot and logs. #50's second criterion moves to #171.

## Consequences
- **Supersedes, for M1 only,** ADR-0026's "Every secret-bearing field is masked in every screenshot" and its consequence that local screenshots can show a reflected secret. The rest of ADR-0026 stands.
- **No M1 file holds pixels,** so ADR-0026's pixel-reflection residual has nothing to apply to until M2.
- **M2's masking has to be established where the capture happens,** not by an overlay the page can reach: a mechanism that sets the final geometry and the mask in one trusted capture step, or keeps the page's rendering frozen through it. It has to defeat both measured attacks and hold for a field that moves away and back during the capture, closed shadow roots, re-rendering, frames, scrolling, fractional geometry and device scale, under sandboxed Chromium, with no path that saves an unmasked image. Checks before and after the capture, retries, and masking a rectangle afterwards are not proof.
- **The run record's contents are pinned:** `test_evidence.py`'s `test_the_run_record_holds_only_the_steps_and_each_steps_evidence` lists every file a hostile replay leaves, so a step that saved anything else would fail it.
- No dependency, paid resource or model call.

## Amendment (2026-10-27): the capture exists, and no run path saves one yet (#171)
- **The mechanism is ADR-0034's.** Once `fill_secret` has handed the page a value in the browser session, a screenshot is a render of the page's scrubbed snapshot, captured with no script and no network; before that, the live page's. It meets this ADR's bar: the masking is in the capture, not in anything the page can reach. The hostile pages of both reviews of #171, M1's two attacks among them, show no bound value in 8 captures each.
- **"No binary writer" no longer holds.** `RunRecord.write_screenshot` writes a `Screenshot`, which only `aqa_runner.screenshots.take_screenshot` makes. Still, no run path calls either until #251, after #250's OCR check, so the run record's pinned contents (`test_evidence.py`) stand.

## Amendment (2026-10-28): the OCR check is in place (#250)
- In a run that binds a test secret, `take_screenshot` OCR-checks every image it captures, live or rendered, from the first capture, before a `Screenshot` exists, and withholds one whose text spells a bound value (ADR-0035). A run that binds nothing runs no OCR. No run path saves a screenshot until #251, so `test_evidence.py`'s pinned contents still stand.

## Amendment (2026-11-14): the paths that save screenshots (#251)
- **Exactly two paths save an image**, each through `aqa_runner.evidence.capture_evidence`, which holds the one call of `take_screenshot` and of `RunRecord.write_screenshot` in the packages' source:
  - `evidence/<seq>/screenshot.png`, for a step that drifted or failed, in `aqa replay`, `aqa run` and `aqa heal <spec>`, which all replay through `strict_replay`;
  - `heals/<key>/screenshot.png`, at a heal's first look. Its later looks save none.
- **Nothing else saves one.** A completed step saves none, and neither do explore (its attempts and its confirmation replay) or the bench pilot. No image reaches a model: a heal's requests are as before, and sending one is #252's and #256's.
- **Decisions** (the maintainer may escalate the fourth, a product call):
  1. The file is `screenshot.png` in both folders, a name that leaves the follow-up's before/after choice open.
  2. Explore and the bench pilot are left out by an opt-in flag that only `strict_replay` sets (`executor.RunSetup.screenshots`, off by default), so a new caller can't save page pixels by accident.
  3. `replay.json` stays schema 1. Each verdict's `evidence.screenshot`, always null before, describes the step its `evidence.path` cites: `{path, withheld}`, or null when that step asked for none; in `aqa run`, each `heal` object gains `screenshot` in the same shape, for the heal's first look (DATA_MODEL §7).
  4. An OCR engine error withholds the capture instead of propagating (ADR-0035's #251 amendment).
  5. A page off the run's allowed origins, or a frame change during the capture, withholds it with a fixed reason and records no policy event, as evidence's own look records none (`take_screenshot(session, record_refusal=False)`).
  6. A write the disk or a link refuses still raises, as every evidence write does: the disk's is a `record_error` stop in replay, and the heal's record-error stop in a heal.
- **A withheld capture** writes nothing and changes no step outcome, verdict, reason or exit code. Its fixed reason, which never quotes the page, is kept only in `replay.json`, scanned with the run's scan as every reason is. A drifted step whose heal gave up saves two images, the heal's look and the kept step's, which can show different moments.
- **A capture on a page that never answers again** is withheld within `CAPTURE_SECONDS`: `screenshots._devtools` detaches only once its calls have answered, so a failed step on a stalled page can't hold the run (LAB_NOTES, 2026-11-14).
- **The run record's pinned contents:** `test_evidence.py`'s `test_the_run_record_holds_only_the_steps_and_each_steps_evidence` now asks for screenshots in its hostile replay, as `strict_replay` does, and lists exactly one new file, `evidence/3/screenshot.png`, for its drifted step.
- **Amends ADR-0024's #243 "Observation before screenshots":** a heal's first look keeps a masked screenshot as evidence, and a verdict cites it, while the healer still reads only the accessibility tree.
- **Left to follow-ups:** the "before" screenshot, with what "before" and "after" mean for a drifted step, and the report's Screenshot tab and its swipe.

## Amendment (2026-11-14): the "before" screenshot, opt-in (#314)
- **The switch is a CLI flag, `--before-screenshots`,** off by default, on `aqa replay`, `aqa run` and `aqa heal <spec>` (API.md §7); `aqa heal apply` refuses it as a usage error (exit 2), as it refuses `--url`. The options:
  1. **A CLI flag** (chosen). The capture's cost is a choice for one invocation: a person debugging a failure turns it on for one run, and CI turns it on in its workflow's command. It adds no project-config schema, changes nothing in DATA_MODEL §9, and is no setting that explore and the bench pilot would read and ignore; API.md §7 is already the CLI's contract.
  2. **A `config.yaml` key.** Rejected: every run of the project would pay for the capture until someone edited the file, the key would join DATA_MODEL §9's schema, and explore and the bench pilot would read a setting they ignore.

  The flag reaches `executor.RunSetup.before_screenshots` through `strict_replay` and `replays.Replaying`, as #251's `RunSetup.screenshots` now does; explore's confirmation and the bench pilot build their `Replaying` without either. No environment variable is added. The approver may escalate the choice, a product call.
- **The capture point.** With the flag, each compiled step's page is captured right before the step runs: before its probe baselines, its target's look, the rebind gate and its intent line, so every way a step can fail has a "before". The capture is `evidence.held_screenshot`, which holds the packages' one call of `take_screenshot(session, record_refusal=False)`: masked once a secret was filled, OCR-checked in a run that binds one, and with the same three withheld branches and fixed reasons, none of which records a policy event. It is held in memory until the step's outcome is known, and `capture_evidence` writes it, through the packages' one call of `RunRecord.write_screenshot`, only when its caller passes it in.
- **Only a failed step keeps its capture,** as `evidence/<seq>/before_screenshot.png`, beside the `screenshot.png` it saves, which keeps its name and stays the page after the step; a step a repair inserted that `executor._shown` failed, and one that failed before its dispatch, at a baseline, its look or the rebind gate, keep theirs too. A completed step drops its capture. A drifted step drops its capture and keeps only its `screenshot.png`, and seq 0, the start navigation, has no page ahead of it and gets none (the maintainer's answer 2a). A drifted attempt a repair took drops its capture, and the step that then runs is captured again; a step a repair inserted is captured as any step is. A dropped capture leaves no file and no reason.
- **`replay.json` stays schema 1.** Each verdict's `evidence` gains `before_screenshot`, which describes the step its `evidence.path` cites, as `screenshot` does: `{path: "evidence/<seq>/before_screenshot.png", withheld: null}`, `{path: null, withheld: "<reason>"}`, or null when that step kept none. The key is in every verdict, flag on or off, so every reader sees one shape. `aqa run`'s `heal` object, `run.json`, `repairs/*.json`, `heals/*`, `egress.json` and the CLI's lines are unchanged. `RunResult.before_shots` holds, by seq, what became of each failed step's capture.
- **A withheld "before"** writes nothing, records no policy event, and changes no step outcome, verdict, reason, run outcome or exit code; its fixed reason is kept only in `evidence.before_screenshot`, scanned as every reason is. A write the disk or a link refuses still raises, a `record_error` stop.
- **The capture changes no result.** On a page that behaves the same, a run with the flag and one without give the same steps, assertions, invariants, policy events, snapshots and verdicts but the new key, a secret filled too (`packages/runner/tests/test_replay_before_screenshots.py`). Without the flag no capture is taken ahead of a step. With it, a page that stalls can add up to `CAPTURE_SECONDS` plus `OCR_SECONDS` before each step, which an opt-in path accepts; the bounds are unchanged. The pull request states the measured cost per step. RapidOCR runs locally (ADR-0035), so strict replay with the flag still makes no model call.
- **Three paths now save an image,** each through `capture_evidence`: #251's `evidence/<seq>/screenshot.png` and `heals/<key>/screenshot.png`, and `evidence/<seq>/before_screenshot.png`, for a step that failed with the flag. This supersedes in part the #251 amendment's "Exactly two paths save an image" and "Nothing else saves one", and closes its "before" follow-up. A drifted step, a heal's first look, explore and the bench pilot save no "before", and neither does a `model_verify` check's own folder. In `aqa replay --mode verified --before-screenshots`, a step that fails saves its "before" as strict replay does, and that image is never sent to a model: the verifier sends only its check's own capture (ADR-0024's #256 amendment).
- **The run record's pinned contents:** `test_evidence.py`'s `test_the_run_record_holds_only_the_steps_and_each_steps_evidence` lists the same files for its drifting hostile replay with the flag off and on, and for a hostile replay whose last step fails, with the flag on, exactly the same base files plus that step's `screenshot.png` and `before_screenshot.png`.
- **Left to a follow-up:** showing the "before" image in the report.

## Amendment (2026-11-14): a fourth path, whose image a model is sent (#256)
- **A fourth path saves an image:** `verified/assertion-<index>/screenshot.png`, for each `model_verify` check `aqa replay --mode verified` would ask the verifier about, through `evidence.capture_evidence` as the other three are, beside that look's snapshot and empty logs, and never a "before" (ADR-0024's #256 amendment).
- **It is the first whose image reaches a model,** which supersedes in part the #314 amendment's "no image reaches a model". The verifier's `Shot`, the only one that asks for it (`Asked(after=True, sent=True)`), keeps the `Screenshot` `take_screenshot` made and `RunRecord.write_screenshot` wrote, out of every repr and document; every other `Shot` keeps none. That object is the only image the verifier's request takes (`verifier.verify_request` raises `TypeError` for anything else, such as bytes read back from the record). So the image sent was masked once a secret was filled and OCR-checked in a run that binds one, as every saved image is. With `--before-screenshots` too, each request still carries exactly one image, its check's own (`test_with_before_screenshots_each_request_sends_only_its_own_capture`). `tests/test_image_exits.py` is unchanged: no new capture.
- **What is withheld** is unchanged: a withheld capture writes nothing, and the check is `inconclusive` with no call. A target that drifted, or a run the gates stop first (an interruption, an earlier call with no response, a spent budget), saves no folder.
- The other three paths still send no image to a model, and vision fallback's is #252's.

## Amendment (2026-11-16): a fifth path, pixel_diff's crop (#324)
- **A fifth path saves an image:** `pixel_diff/assertion-<index>/crop.png`, for a `pixel_diff` check that failed, or whose baseline was refused (P7 to P11), in a run `strict_replay` makes, so in `aqa replay`, `aqa run` and `aqa heal <spec>` (ADR-0025's #324 amendment; DATA_MODEL §7, *Pixel diff*). `<index>` is the check's place in the script's assertions, since an id may hold `/`. A pass, a refusal about the page (P1 to P6), explore (its confirmation replay has no baselines place) and the bench pilot save none, and so does any replay without `RunSetup.screenshots`, which still only `strict_replay` sets.
- **It is the check's own capture, cut down.** The check takes the page's screenshot through `evidence.held_screenshot`, so `take_screenshot(session, record_refusal=False)`: masked once a secret was filled and OCR-checked in a run that binds one. The crop is made only inside `aqa_runner.screenshots`, by `Screenshot.cropped`, from that `Screenshot` and with its scan, so a record still holds no image no capture checked; it isn't OCR-checked again, since it shows only less of an image that passed. It is written by `evidence.save_crop` through evidence's one `RunRecord.write_screenshot` call, and a write the record refuses raises, as every evidence write does. No new call of `take_screenshot` or `RunRecord.write_screenshot` is in the packages' source, and `tests/test_image_exits.py` is unchanged.
- **Why it is saved, and when** (#324's spec, choice 2 of ADR-0025's #324 amendment): a person makes a check's baseline by copying the crop a failed or refused check leaves, then pasting its sha256, so no command or flag writes into the repository. The crop is kept only where a check didn't pass, as this ADR keeps an image only where something didn't complete.
- **No image reaches a model from it.** The crop is never sent, and `replay.json`'s schema and verdicts are unchanged: no verdict cites it. The verified path and heal's vision fallback are still the only paths that send an image (the #256 amendment, ADR-0002's #252 amendment).
- **A withheld capture saves nothing:** the check is refused with `pixel_diff's screenshot was withheld` (P4), and there is no crop to keep.
- **Maintainer decision** (2026-11-16, on PR #331): this fifth path, and SECURITY §5's wording that a baseline leaves the machine by the committing person's reviewed choice, are accepted, with one step added. The crop isn't OCR-checked again and can show page content no test secret binds, so DATA_MODEL §7's *Making a baseline* tells that person to look at the crop for anything sensitive before committing it.
