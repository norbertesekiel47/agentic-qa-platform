# ADR-0031: Renovate for weekly dependency updates, and how a bump keeps TECH_STACK.md true

- Status: Accepted
- Date: 2026-10-01

## Context
TECH_STACK.md §7 promises weekly dependency updates, and #34 committed `uv.lock`, but nothing updates it (#62). Four facts shape the choice:
- **The pins are exact and live in several files.** ADR-0027 pins every dependency in the member that uses it (`==`), the dev tools in the root, and TECH_STACK.md §1 repeats the versions. A bot that bumps a pin and the lock leaves the document behind.
- **uv is held to 0.11.** The root `required-version` is `>=0.11.15,<0.12`, and uv refuses to run outside it.
- **litellm stays out.** `constraint-dependencies = ["litellm<0"]` makes any resolution that pulls it in fail (ADR-0007 amendment, ADR-0027).
- **The hosted Renovate app runs no `postUpgradeTasks` by default**, so it can't regenerate a document after a bump (the [option's docs](https://docs.renovatebot.com/configuration-options/#postupgradetasks): "In Mend-hosted Renovate apps, commands remain blocked by default").

A research pass on 2026-10-01 checked the tools' source and docs and ran Renovate 44.131.3 locally (`--platform=local --dry-run=lookup`) against a copy of the repository.

## Options
- **Tool:** (1) Dependabot; (2) Renovate through the Mend-hosted GitHub app.
- **Scope:** (1) Renovate's defaults; (2) a whitelist of the `pep621` manager plus a regex manager for TECH_STACK.md.
- **Keeping TECH_STACK.md true:** (a) the bot's pull request edits the document's versions; (b) trim the document to the versions that matter to the design and point to `uv.lock` for the rest; (c) a check that fails when a pin and the document disagree; (a) with (c).
- **Cadence:** (1) every update in one pull request; (2) one weekly group for minor and patch updates, with majors and risky packages on their own.
- **`bench/harness/checks-requirements.txt`:** (1) the bot updates it; (2) the bot leaves it alone.
- **Release age:** (1) none; (2) a 3-day minimum.

## Decision
- **Renovate, hosted app.** Dependabot's uv helper pins uv 0.12.x (`dependabot-core`, `uv/helpers/requirements.txt`, per the triage of #62), so against our `<0.12` it reports `tool_version_not_supported` and opens nothing; no setting pins its uv. Renovate runs a uv in range, and `uv lock --upgrade-package` still applies `constraint-dependencies`.
- **`.github/renovate.json` sets `constraints.uv`.** Renovate takes the uv version from `tool.uv.required-version` of the pyproject it is updating ([pep621's uv processor](https://github.com/renovatebot/renovate/blob/7c914c63ebbc6946fc65c4e18a92747c212bd570/lib/modules/manager/pep621/processors/uv.ts), L220-227), and only the root has one. A member's update would get the latest uv, which the workspace refuses (LAB_NOTES, 2026-10-01). The [`constraints`](https://docs.renovatebot.com/configuration-options/#constraints) option comes first in Renovate's order, and a test holds it equal to `required-version`.
- **Only `pep621` and `custom.regex` run** ([`enabledManagers`](https://docs.renovatebot.com/configuration-options/#enabledmanagers)), and the `requires-python` and `build-system.requires` dependency types are off. Renovate's defaults would open pull requests for `ci.yml`'s SHA-pinned actions (#82's file), Dockerfile digests, `.python-version`, the `requires-python` lower bound and the `uv_build` range, and would match `checks-requirements.txt`. Python moves by hand with ADR-0027's checklist, and uv with the list under Consequences. The local run reports `python` and `uv_build` as `disabled`.
- **The bot's pull request edits TECH_STACK.md, and a test is the tripwire** (a with c). A version in §1 that is an exact pin carries an HTML comment, `renovate: NAME`, after it. A regex manager reads those ([the documented annotation pattern](https://docs.renovatebot.com/modules/manager/regex/)), so a package's pin and its tracked version are updates of the same dependency, and one branch holds both: [`groupName`](https://docs.renovatebot.com/configuration-options/#groupname) puts them in one pull request, and for an ungrouped update both managers give the same branch name (the local run showed this for the weekly group, a major and Playwright). `tests/test_dependency_updates.py` fails when the exact pins and the tracked versions differ in any way: a pin with no tracked version, a tracked version with no pin or a stale one, or a package pinned or tracked at two versions. Without the test, a missing comment or a hand edit would go unnoticed. Without the bot, every weekly pull request would be red until a person edited about 20 versions.
  - **Rejected, (b):** it moves "which version" away from the document AGENTS.md §2 names as its owner, and rewrites most of §1's rows, which new-dependency tickets also edit.
  - **What the rule asks of later tickets:** a new exact pin needs a tracked version in §1, which "update TECH_STACK.md for a new dependency" already implied. A version without the comment is the pick as of the date at the top of the file, until a ticket adopts it.
- **Weekly, grouped, with majors alone.** The `schedule:weekly` preset is "before 4am on Monday" ([presets](https://docs.renovatebot.com/presets-schedule/#scheduleweekly)), and the config sets `timezone` to UTC because Renovate otherwise evaluates a schedule in the local time of the machine that runs it. Minor and patch updates are one pull request. [`separateMajorMinor`](https://docs.renovatebot.com/configuration-options/#separatemajorminor), true by default, "has priority over package groups configured by packageRule", so each major arrives alone (TECH_STACK.md §7). [Lock-file maintenance](https://docs.renovatebot.com/configuration-options/#lockfilemaintenance) is on, and is its own pull request: with exact pins, it is the only thing that moves transitive packages, which is where most advisories land. Automerge, a dependency dashboard, labels and assignees are off.
- **Pre-1.0 minors get a pull request each.** SemVer lets a 0.x release change anything ([Renovate's own warning](https://docs.renovatebot.com/configuration-options/#packagerulesmatchupdatetypes)), and a Ruff minor routinely changes lint output; in the group it would block every other update. A rule with `matchCurrentVersion: "/^0\\./"` sets `groupName: null` for minors; their patches stay in the group.
- **Playwright gets its own pull request**, because it must move with the checks image (below).
- **A release must be 3 days old** ([`minimumReleaseAge`](https://docs.renovatebot.com/key-concepts/minimum-release-age/)). It limits the exposure to a compromised release of a dependency Renovate bumps, the class of risk that litellm (ADR-0007 amendment) and Trivy (#30) already show, but not for everything (see the gaps below). [`internalChecksFilter`](https://docs.renovatebot.com/configuration-options/#internalchecksfilter) defaults to `strict`, so a pending release gets no branch and no pull request; the local run marked releases less than 3 days old as pending. A test holds the age, the filter and the rule that a release with no timestamp counts as pending.
- **`bench/harness/checks-requirements.txt` stays out of the bot's scope.** Its one direct pin is Playwright, which must move with the base image's tag and digest in `checks.Dockerfile` (ADR-0023, "Pins move together"). Nothing in CI builds or runs that image (ADR-0029), so a green bot pull request would prove nothing about it. It was compiled with `--no-header`, which [the pip-compile manager can't read](https://docs.renovatebot.com/modules/manager/pip-compile/), and regenerating it with a header would buy bumps nobody can verify. The [`pip_requirements` manager](https://docs.renovatebot.com/modules/manager/pip_requirements/) matches the file by default, and the whitelist keeps it out. The safeguard is a test that the `.in`, the `.txt` and the Dockerfile tag name the workspace's Playwright version, so a Playwright pull request is red until a person regenerates the image's lock and bumps its tag. The test compares versions only: the digest and the hashes stay a person's job, and nothing in CI checks them. The dependency audit reads the file's pins since #71 (ADR-0029's amendment), so an advisory against one still turns pull requests red; the fix is the Dockerfile's command with `--upgrade-package`.
- **litellm still fails.** A resolution that pulls it in makes `uv lock` fail, Renovate reports the artifact error, the pull request's lock stays stale, and `uv sync --locked` fails in the `python` job. A test runs `uv lock` offline against fake wheels, with the real constraint and without it. The lock's contents are #67's test.

## Consequences
- **Install order.** The config is read from the default branch, and committing it onboards the repository ([docs](https://docs.renovatebot.com/getting-started/installing-onboarding/)). The maintainer merges this change first, then installs the Mend Renovate app on this repository only; the other order opens a "Configure Renovate" pull request with a default `renovate.json`. No secret is needed. Pull requests appear in the Monday window.
- **A third-party app can push branches, workflows included.** It asks for write access to code, checks, commit statuses, issues, pull requests and workflows ([permissions](https://docs.renovatebot.com/security-and-permissions/)). As configured it edits only the `pyproject.toml` files, `uv.lock` and TECH_STACK.md, but nothing in GitHub stops it from pushing more, and a pull request runs its own `ci.yml`, so the five required checks (ADR-0019) can't vouch for a change to the workflow itself. The controls are that nothing automerges (a test walks the whole config for it) and that the maintainer reads each bot pull request's file list before merging. The M8 deploys' IAM trust policies (SECURITY.md §11) must bind to `main` or a protected environment, never to every branch. The Mend app's pricing is unverified.
- **The age limit has gaps.** Renovate applies it to the versions it proposes. When it delegates to the package manager (lock-file maintenance, or the transitive packages a bump pulls in), only npm and Poetry receive the cutoff ([docs](https://docs.renovatebot.com/key-concepts/minimum-release-age/)), not uv. A malicious transitive release can therefore reach a bot pull request's CI before anyone reviews it, with CI's read-only token and no secrets. uv's `exclude-newer` would close it, but it is a `[tool.uv]` setting, which asks for the maintainer's approval: a follow-up ticket, not yet filed. Turning lock-file maintenance off would narrow the gap, and leave transitive packages unmoved; it stays on, for the weekly refresh of `uv.lock` the ticket asks for.
- **Security fixes wait for Monday.** Renovate's vulnerability pull requests are immediate and have no age limit, but they need GitHub's dependency graph and Dependabot alerts ([docs](https://docs.renovatebot.com/configuration-options/#vulnerabilityalerts)). The graph doesn't read `uv.lock` (ADR-0029), and alerts are off here (`gh api repos/norbertesekiel47/agentic-qa-platform/vulnerability-alerts` returned 404 on 2026-10-01). A high advisory turns the required `dependency-audit` check red until its fix arrives by hand, or in the next Monday window once a direct dependency's fix is 3 days old (lock-file maintenance, which has no age filter, moves transitive ones). Renovate's experimental [`osvVulnerabilityAlerts`](https://docs.renovatebot.com/configuration-options/#osvvulnerabilityalerts) would raise immediate fix pull requests for direct PyPI dependencies without GitHub's graph; it is not enabled, because it is experimental and its pull requests would skip the age limit.
- **Red pull requests are expected.** A Playwright update, until the image is regenerated. The weekly group, when one update breaks a gate: fix it on the branch, or exclude the package. A pull request whose update needs litellm.
- **Moving uv, Python or an action stays by hand.** A uv bump edits `required-version`, `constraints.uv`, `ci.yml`'s version and sha256, the `uv_build` ranges, the spike Dockerfile's uv image and TECH_STACK.md; this list is the owner, and only `constraints.uv` has a test.
- **Not covered:** GitHub Actions and the tools `ci.yml` downloads, Dockerfile digests, and the dashboard's `pnpm-lock.yaml` (M7, with an npm manager and `ignorePaths` for `bench/apps`).
- **Cost:** no AWS resource and no LLM call. CI on GitHub-hosted runners is free for public repositories; on Blacksmith (ADR-0019), each bot pull request spends the `python` job's paid minutes.
