# ADR-0026: The browser boundary for local and CI runs: sandbox, egress and test secrets

- Status: Accepted. The Evidence decision's masked screenshots are superseded for M1 by [ADR-0033](0033-m1-saves-no-screenshots.md).
- Date: 2026-09-29

## Context
M1 runs the first model-using agent against real pages, locally and in our own CI, before any hosted runner exists. SECURITY §5–§7 describe the controls mostly from the hosted side, and several of them don't fit M1:
- **Sandbox.** GitHub's ubuntu-24.04 runners restrict unprivileged user namespaces through AppArmor (`kernel.apparmor_restrict_unprivileged_userns=1`), so Playwright's Chromium can't start its sandbox there. ARCHITECTURE §5 said CI runs "attempt the sandbox and warn", and policy_guard refuses the code for that unless an ADR is cited.
- **Loopback and private addresses.** SECURITY §7 refused them in every mode, but local runs target `http://127.0.0.1:4100` and CI previews may be private.
- **Secrets move into M1.** Four of the five pilot specs sign in with `TEST_PASSWORD`, and redaction applies in every model-using mode (AGENTS.md §6). So `fill_secret`, its binding and redaction move from M2 into M1. Local runs had no source for secret values or bindings.
- **Third-party hosts.** Apps load CDNs, fonts and analytics. A refused request logs a console error and can leave an image broken, and the invariants would blame both on the app (DATA_MODEL §6).
- **Codex's review** of the M1 decisions (gpt-6-astra, 2026-09-29) found four gaps in the first draft:
  - a spec could widen a secret's destinations by changing its start URL;
  - a click, redirect or popup could turn a resource-only host into a document the agent acts on (Playwright's routes don't see redirect hops; LAB_NOTES, 2026-09-29);
  - hiding the symptoms of blocked requests could hide real defects;
  - allowlisted hosts could resolve to internal services.

## Options
- **Sandbox:** (1) a hard error everywhere in M1; (2) warn and continue in CI.
- **Sandbox in our CI:** (1) set the AppArmor sysctl on the GitHub-hosted runner; (2) run browser tests in a container with Playwright's seccomp profile.
- **Private addresses:** (1) refused everywhere; (2) allowed everywhere outside hosted runs; (3) allowed only for the invocation's target and for private origins the project declares.
- **Secret bindings:** (1) in the project config, with values from prefixed environment variables; (2) in each spec; (3) bare environment variable names.
- **Blocked requests:** (1) never count their symptoms; (2) count everything; (3) a blocked request keeps the run from passing, except for declared expected-blocked hosts.
- **Reporting an egress block:** (1) its own exit code (6) and run state (`errored`, `egress_blocked`); (2) reuse the infrastructure codes (10+); (3) explore reuses the spec-error code (5), and replays reuse 10+.
- **Saved evidence:** (1) never save request or response bodies, HAR files or Playwright traces; (2) ban them in M1 only, until a scrubber covers them.

## Decision

### Sandbox
- **Always on.** Chromium launches with `chromium_sandbox=True`.
- **Hard error in M1.** Everywhere in M1, a launch that can't sandbox is an error, with a message that says how to fix the host.
- **Startup check.** The check proves the sandbox is on:
  - it compares a renderer process with the browser process: namespaces and seccomp mode, allowing for the zygote;
  - it includes negative controls;
  - macOS uses its own method.
- **Our CI** records the runner's AppArmor state, then sets `kernel.apparmor_restrict_unprivileged_userns=0` before the browser tests. This is Chromium's documented fix, and the runner is discarded after the job. Browser tests move into the runner image once it exists.
- **Customer CI.** Whether customer CI may ever run unsandboxed is decided with the Action at M5 (#26).

### The browser's environment
The browser launches with an explicit, minimal environment: no provider keys, no `AQA_SECRET_*` values and no cloud credentials. A test secret reaches the browser only through `fill_secret`.

### Two tiers of hosts
- **Allowed origins** are the start origin plus the origins the spec lists. The agent may navigate and act only there, and a secret can be bound only to them.
- **Subresource hosts** are declared in the project config. Pages may load resources from them.

The egress proxy lets traffic through to both tiers. Before every observation and every action, the tools check the origin of the top-level page and of the target's frame. A document from any other origin is a policy event:
- the agent can't observe it or act on it;
- the agent may only navigate back to an allowed origin, or restart.

Popups are recorded and closed. The redirect hop itself isn't blocked, because its host is already on the egress allowlist. The tiers limit what the agent may do, not where traffic may go.

### Start origin
The start origin comes only from the invocation (`aqa explore --url`) or the project config (`base_url`, DATA_MODEL §9), never from the spec. `start_url` must be a path.

### IP policy by location
- **Every mode:**
  - the proxy passes only allowed origins and subresource hosts;
  - link-local and cloud-metadata addresses are always refused;
  - IP forms are normalized, including IPv4-mapped IPv6;
  - each hostname's first validated DNS answer is pinned for the whole run, so it can't rebind mid-run.
- **Hosted runs** may reach public addresses only.
- **Local and CI runs** may reach loopback and private addresses only for the invocation's target origin and for private origins the project config declares. Every other host must resolve to a public address.
- **Same rules for every request.** They cover every redirect hop and the runner's own probe and reset requests. Those requests go to allowed origins only and carry none of the browser's cookies.
- **Other transports.** Chromium launches so that no UDP traffic bypasses the proxy (WebRTC). The egress tests cover WebSockets, QUIC, IPv6 and DNS prefetch, observed at the packet level.

### Test secrets
- **Bindings live in the project config**, and a spec may reference only declared secrets. Each binding names:
  - the origins the secret may be filled on: `start` means the invocation's start origin, and any other must be an allowed origin;
  - the field it may go into: `password` means an `<input type="password">`; otherwise a role and accessible name.
- **Destinations.** A secret's destinations are the intersection of its binding and the run's allowed origins.
- **Values** come from `AQA_SECRET_<NAME>` environment variables, locally and in CI. Hosted runs keep the `test_secrets` API.
- **CI's trusted revision.** Whether a CI run trusts the base branch's config or the pull request's is decided at M5 (#27).

### Egress blocks
- **Default.** A request to a host that is neither an allowed origin nor a subresource host is refused and recorded. The egress block keeps the run from passing: it is a policy outcome, neither a pass nor a finding.
- **Reporting (option 1).** The run ends `errored` with `error_code: egress_blocked` and no verdict, the run record names the refused host, and the CLI exits 6 (API.md §7). CI can tell our sandbox stopping a run apart from an app bug (exit 1) and a broken environment (10+).
- **Expected-blocked hosts.** If the project config lists the host as expected-blocked, the block's direct symptoms don't count against invariants: its console error and a broken image, matched by the failed request, never by console text. Indirect effects, such as app code that fails because a script didn't load, still count.
- **The proxy never invents a response** the page could count as the app's. On an upstream failure it drops the connection or fails the tunnel, and records an infrastructure event. An unreachable start origin is an infrastructure error (exit 10+), not a finding.

### Evidence (option 1)
- Text observations are redacted before any model sees them (SECURITY §5).
- Every secret-bearing field is masked in every screenshot. *Superseded by ADR-0033:* M1 takes no screenshots, and bound-field masking moves to M2.
- **Never saved, in any milestone:** request or response bodies, HAR files and Playwright traces. Request bodies are where secrets travel (a sign-in POST carries the password), and reliably scrubbing a trace's page snapshots and bodies isn't worth a debugging convenience.
- Network evidence is metadata only: method, redacted URL, status, timing and size (`network_log`, DATA_MODEL §2).
- Text redaction runs over everything that is saved.
- OCR checks for secrets that a page reflects into pixels arrive with hybrid perception in M2, before any artifact can leave the machine. Uploads start in M4.

## Consequences
- **Explore runs behind the proxy from its first commit.** The egress, origin-check and injection tests block merges from M1 on (TESTING §1).
- **The CI workflow gains a sysctl step.** Like any gate change, it needs the maintainer's approval under the guard.
- **An undeclared third-party host stops a confirmation replay**, with a message that names the host to declare. Conduit makes no third-party requests.
- **Local screenshots can still show a secret that a page reflects** until M2's OCR checks. That stays within SECURITY §5's best-effort class, and M1 uploads nothing. *Superseded by ADR-0033:* M1 saves no screenshots.
- **Later milestones decide:**
  - the Action's sandbox (#26);
  - the CI run's trusted config revision (#27);
  - the hosted-run policy for subresource hosts (#29).
- **Docs updated:** SECURITY §5–§7 and ARCHITECTURE §5 are amended to match.

## Amendment (2026-09-30): how the sandbox check works (#35)

The Decision's "startup check" is called the **sandbox check** (CONTEXT.md), so it can't be confused with startup hygiene (SECURITY §6).

- **When it runs.** `aqa_runner.sandbox.launch` asks for `chromium_sandbox=True`, then opens a blank page in a context of its own, because a renderer exists only once a page does. It checks every renderer alive at that moment and closes the context before it returns the browser. Later renderers start with the same sandbox (on Linux, from the same zygote) and aren't checked again.
- **Process IDs** come from CDP's `SystemInfo.getProcessInfo`, an experimental domain that lists the browser's and each renderer's PID as the host sees them. That holds only for a browser launched on this host, never one connected to, which is why `launch` runs the check. The alternative, walking the process tree from Playwright's driver, has to work around the zygote (a renderer's parent) and can't tell two browsers apart.
- **Linux: strict.**
  - The renderer must be in its own user, pid and net namespaces.
  - It must carry more seccomp filters than the browser (`Seccomp_filters` in `/proc/<pid>/status`, Linux 5.9 and later).
  - The seccomp mode can't serve. In a container whose seccomp profile lets the sandbox start, such as Playwright's, every process, the browser included, is already in mode 2 (measured: 1 filter on the browser, 2 on the renderer).
  - Chromium's setuid sandbox, which Playwright's builds don't ship, would fail this check, and a kernel too old to report the count stops it with an error of its own. Neither ever passes.
- **macOS.** The check calls libSystem's `sandbox_check(pid, NULL, 0)`, which Apple exports but doesn't document.
  - The renderer must be sandboxed and the browser not. The browser's "no" also shows the call can answer no.
  - It also answers "sandboxed" for a PID with no running process, a zombie or one already reaped. So the process must still be running once it has answered (`proc_pidpath` finds it), or the check stops with an error.
  - If Apple changes the call, the comparison fails and the launch is refused. It can't pass.
- **Other operating systems** have no sandbox check, so their launches are refused.
- **Failures.** Both cases raise `SandboxUnavailableError`, with exit code 10 (API.md §7): a launch whose sandbox can't start (Chromium's `No usable sandbox!`, passed through in Playwright's error), and a launch whose sandbox the check can't prove.
  - The message names the host fix. On Linux: the AppArmor sysctl for throwaway hosts, Chromium's AppArmor profile for machines you keep, and Playwright's seccomp profile in containers.
  - An error while reading the processes (a kernel without the count, a renderer that exits mid-check) propagates as it is. The browser is closed first, so nothing passes.
  - The CLI maps the error to its exit code once a command launches a browser (#53).
- **Residual risk.** The check trusts a PID for the moments between CDP's list and its reads. A renderer that exits and whose PID another process takes in that window could be read as that process, on either OS. PIDs are allocated in sequence, so that takes a host forking tens of thousands of processes within microseconds, and the blank page gives page content no way to end the renderer. Comparing macOS's per-process unique ID before and after `sandbox_check` would close it.
- **Nothing skips the check.** `launch` takes no option and reads no setting or environment variable. The check measures the renderer itself, so every way of turning the sandbox off fails it, for every browser launched through `launch`. Every run's browser must be: #36's session launches through it. Nothing yet stops other code from calling Playwright's launch directly. The negative controls in `packages/runner/tests/test_sandbox.py` launch without the sandbox, the only place allowed to.
- **CI.** The `python` job installs Playwright's headless shell, logs `kernel.apparmor_restrict_unprivileged_userns`, sets it to 0, and runs the browser tests within `pytest --cov`. A runner without the setting fails the job.

## Amendment (2026-09-30): a browser running as root (#37)

Chromium won't start its sandbox in a browser that runs as root, a container's default user. Its zygote logs "Running as root without" followed by the switch that turns the sandbox off, and Playwright raises the same `TargetClosedError` it raises for `No usable sandbox!`. `launch` now recognizes that line too and raises `SandboxUnavailableError` (exit code 10), whose message says to run the runner as a non-root user. Before this, the error passed through as Playwright's own.

## Amendment (2026-10-01): the browser session (#36)

Every browser a run uses comes from a **browser session** (CONTEXT.md): one for each attempt or replay, opened by `aqa_runner.browser_session.open_browser_session`, for explore and replay alike. It launches through `launch`, so the sandbox check runs for every session. #44's document-origin checks will live in it too.

- **The browser's environment is empty.** `launch` passes Chromium `env={}`; Playwright's default is the runner's own environment ([`env`](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-option-env)). The `Chromium` protocol takes `env` for this, and `launch` still takes no option. No Chromium process holds the runner's provider keys, cloud credentials or `AQA_SECRET_*` values, and no proxy variable of the host's can steer the browser. The session's tests read each Chromium process's environment (`/proc/<pid>/environ` on Linux, `ps -E` on macOS, with a positive control for the reader), in CI on Linux and locally on macOS. The hosted runner image isn't covered yet: the spike's image has no fonts (LAB_NOTES, 2026-10-01), and its `HOME=/tmp` no longer reaches the browser.
  - *Residual risk:* Playwright's driver (a Node process) and the runner itself keep the runner's environment. They run as the same user as the browser, so an exploit that escapes the sandbox can read them; the sandbox, and on hosted runs the VM, are the defences there. The empty environment stops the accidental paths: inherited variables, crash reports and child processes.
- **Fresh state.** Each session launches its own browser. Playwright gives each launch a new, randomly named profile directory (`playwright_chromiumdev_profile-*` in the temp directory) and deletes it when the browser closes, so the session makes none of its own. The page runs in a new context, never a persistent one, which refuses downloads (`accept_downloads=False`; Playwright accepts them by default, [`accept_downloads`](https://playwright.dev/python/docs/api/class-browser#browser-new-context-option-accept-downloads)). Blocking service workers belongs to #43.
- **Browser settings.** `aqa_core.browser.BrowserSettings` holds the five settings, with ADR-0025's pins as its defaults. The session applies them to its context, and the caller may pass its own. #39 merges the project's and the spec's overrides into one and validates it, and #45 and #46 record and replay it.
- **Element refs.** The snapshot is Playwright's AI mode ([`page.aria_snapshot(mode="ai")`](https://playwright.dev/python/docs/api/class-page#page-aria-snapshot), added in 1.59), which gives refs to elements that are visible and receive pointer events. Playwright's built-in `aria-ref=` selector engine resolves them against each frame's latest snapshot; it isn't in Playwright's public docs, so the session's tests pin its behavior on 1.63.
  - *Why not Playwright's refs:* they can name a different element in a later snapshot, and otherwise an old one names nothing and the action waits out its timeout (LAB_NOTES, 2026-10-01). Page text can also write `[ref=e2]` wherever Playwright renders text.
  - *Decision:*
    - The session renumbers each element's own ref, the last token of its line's key (page text can't end a key that way), to `e<n>`, a number it never gives again. Every other `[ref=` in the snapshot, which only page text writes, reads `(ref=`; a plain replacement keeps the cost linear in whatever text a page holds.
    - A snapshot retires the earlier refs before it calls Playwright, which may store a snapshot the session never sees. Snapshots and lookups take turns, so no snapshot replaces Playwright's while a ref is being resolved against it.
    - `locate(ref)` resolves only the current snapshot's refs and returns the element itself, which never becomes another element. A ref from an older snapshot, one never given and one whose element, document or frame has gone each raise `RefError`, and no other string reaches a selector.
    - Only the session takes accessibility snapshots of its page, since any other snapshot changes what Playwright's refs resolve to. Keeping the page private to the session is for #44 and #53, which add its observations and actions.
  - *Rejected:* refs prefixed with their snapshot's number (`s3e12`), which need no map but lengthen every ref and expose frame structure, and Playwright's refs unchanged, which can't refuse a stale ref.
  - *Not decided here:* which frame each ref came from, which #44's checks on cross-origin frames need.

## Amendment (2026-10-01): the start URL (#89)

A run's first navigation goes to its **start URL** (CONTEXT.md): the start origin followed by the spec's `start_url` as written. `aqa_core.project.start_url(spec, start)` builds it; the executor's first navigation (#46), explore's and the confirmation replay's (#53) call it rather than building it.

- **Joined as text,** never percent-decoded and never resolved. The start origin has no path, and `start_url` opens with one `/` that no `/` or `\` follows, so a URL parser ends the host at that `/`. Since `start_url` also has no empty, `.` or `..` segment (`%2e` is a dot; DATA_MODEL §6), the path the parser reads, dot segments resolved, doesn't start with `//`. `tests/test_start_url.py` checks both with Chromium's own `URL` parser, against DNS, IPv4 and IPv6 start origins: for `/`, `/%2f%2fevil.test`, `/..;/x` and `//` in a query or a fragment, and for every `start_url` the spec parser accepts of up to 4 characters after the `/` from an alphabet of separators, dots, percent escapes and letters, plus the backslash and whitespace it must keep refusing. Controls show it catches a URL on another origin and a path starting `//`.
- **Why:** some accepted values are safe only as text. A browser keeps `%2f` encoded, but decoded, `/%2f%2fevil.test` is `///evil.test`. Joined to the start origin, that keeps the origin but gives the path `///evil.test`, which a parser resolving the path again, Chromium included, reads as the host `evil.test`. `/..;/x` is no dot segment to a browser, and `//` in a query or fragment names no host.
- *Rejected:* resolving the path, with Python's `urljoin` or against a Playwright context's [`base_url`](https://playwright.dev/python/docs/api/class-browser#browser-new-context-option-base-url), which `page.goto` applies with the `URL()` constructor (`constructURLBasedOnBaseURL` in 1.63's driver). On accepted values both give the same URL, but safety would then rest on a second parser agreeing with the browser's, not on `start_url`'s rules alone. Callers pass the absolute start URL, never the path; `page.goto` re-serializes it with Node's `URL()`, which keeps an absolute URL's origin.
- **Compiled `navigate` paths** (DATA_MODEL §7) are joined to the start origin by the same rule: their single leading `/`, then the path as written, never decoded. One that breaks `start_url`'s segment rule can read as a path starting `//`: `/..//evil.test` reads as `//evil.test`. #45 validates them and #46 joins them.

## Amendment (2026-10-01): what the sandbox check observed (#81)

The spike's trial reported only whether the check proved the sandbox, so #38's outcome ADR could cite a boolean but not the measurements behind it. The check now reports what it read alongside its reasons.

- **What it reads.** `SandboxObservations` holds the browser process and each renderer the check compared with it. On Linux each is a `LinuxProcess`: its PID, its `user`, `pid` and `net` namespace links, and its `Seccomp_filters` count. On macOS each is a `MacProcess`: its PID, and whether `sandbox_check` reported it sandboxed. Nothing new is read.
- **The same reads as the reasons.** `check_processes` returns the observations with its reasons. It reads each process once and compares exactly those reads, so an observation can't vouch for a renderer the check refuses: the report never comes from a second read or a subset. An OS with no sandbox check reads nothing (`None`).
- **How the observations leave the check.**
  - `launch_with_observations(chromium)` runs `launch`'s steps and also returns the observations. A check that read nothing has proved nothing, so a browser it returns always comes with them. `launch` delegates to it and still returns only the browser, so its callers and the existing tests are unchanged.
  - A refusal carries them in `SandboxUnavailableError.observed`. That is `None` when the check read nothing: the sandbox couldn't start, so no browser ran, or the OS has no sandbox check.
  - Neither function takes an option or reads a setting, so nothing skips the check.
  - *Rejected:* `launch` returning a pair, which would change every caller; and reading the processes again after `launch`, which would observe other renderers than the ones judged, and finds nothing once a refused browser is closed.
- **The spike's trial** launches through `launch_with_observations`, where ADR-0008's 2026-09-30 amendment names `launch`. It reports the observations on success and on refusal in a new top-level key, `sandbox_observed` (spikes/hosted-chromium/README.md). Every existing key keeps its value, so trials recorded before this change stay comparable.
  - *Rejected:* nesting the observations under `sandbox`, which would change that key's value.
- **What the check decides is unchanged.** `packages/runner/tests/test_sandbox.py`'s existing tests pass unedited, its negative controls included.

## Amendment (2026-10-01): Chromium starts only behind the sandbox check (#77)

This supersedes the 2026-09-30 amendment's (#35) "Nothing yet stops other code from calling Playwright's launch directly."

- **The gate.** `tests/test_chromium_launches.py` runs within `uv run pytest --cov`. It parses every module in `packages/*/src` and refuses each call of, or reference to, a method that launches or connects to Chromium outside `packages/runner/src/aqa_runner/sandbox.py`. Its message gives the file and line, and names `aqa_runner.sandbox.launch` as the fix. A reference counts as well as a call, so `functools.partial(playwright.chromium.launch)` and a bound method passed on are refused too.
- **The sandbox module** is the only module in `packages/*/src` left alone, and only for the call that the sandbox check follows: the test also requires `chromium.launch` to be the module's only Chromium start, and to sit inside `launch_with_observations`, which `launch` delegates to (the amendment for #81). A second launch or a connection added there fails, and so does moving the start into a helper that other modules could call.
- **What counts.** Playwright's `BrowserType` starts or attaches to a browser through four methods: `launch`, `launch_persistent_context`, `connect` and `connect_over_cdp` ([`BrowserType`](https://playwright.dev/python/docs/api/class-browsertype), 1.63).
  - Only `BrowserType` has the last two, so they count on any object.
  - `launch` and `connect` are common names (`sqlite3.connect`, a socket's `connect`, `aqa_runner.sandbox.launch` itself). They count only on an object spelled as Chromium's `BrowserType`: an attribute `chromium` (`playwright.chromium`), a name `chromium`, or `playwright["chromium"]`.
- **Residual risk.** The test reads spelling, not types, so review has to catch what it can't see:
  - a `BrowserType` under another name or attribute (`browser_type = playwright.chromium`, then `browser_type.launch()`; `self._chromium.launch()`);
  - one reached through `getattr`;
  - an unbound call through the class (`BrowserType.launch(playwright.chromium)`);
  - a start that doesn't go through Playwright's `BrowserType` at all, such as a subprocess running Chromium's binary or a raw CDP connection.

  A type-aware check through mypy's build API would see the first three. It was rejected because it ties a test to mypy's internals and runs a full type check inside pytest.
- **Scope.**
  - The package tests aren't scanned. The negative controls in `packages/runner/tests/test_sandbox.py` launch without the sandbox, and the tests' doubles wrap Playwright's launch.
  - `spikes/` and `bench/` aren't scanned either. The spike's trial launches through `launch_with_observations`. `bench/harness/toggle_checks.py` launches Chromium itself in the checks image, with an empty environment; ADR-0023's 2026-10-01 amendment (#77) records why.
  - Firefox and WebKit launches aren't covered, because nothing here launches them.
- **A test, not a policy_guard rule.** A guard rule would refuse each edit in Claude Code, but the guard matches lines, and every guard change needs the maintainer's approval. CI's pytest binds every agent and person, and an AST walk matches calls and references as such (#77's triage).

## Amendment (2026-10-01): the egress proxy (#42)

The egress proxy lands in three changes. First the egress gate (`aqa_runner.egress.EgressGate`): the run's policy, its DNS pins, its records and `connect`, the only way out. Then the proxy server (`aqa_runner.egress_proxy.EgressProxy`), a class of its own that holds the run's gate, and the browser sessions' use of it. Then runner-side requests, which call the gate's `connect` too. What all three rely on is decided here.

- **Which hosts pass, by host and port.**
  - An allowed origin passes on its own port, or its scheme's default port when it writes none. The scheme isn't compared: a tunnel's `CONNECT` names only a host and a port, and which document may use which origin is the session's check (#44).
  - A subresource host is a bare host (DATA_MODEL §9), so it passes on its scheme's default port only: 80 for a plain proxied request, which is http's, and 443 for a tunnel, which carries https or wss. A `ws://` connection also tunnels, on its default port 80, so it can't reach a subresource host there; written to port 443 (`ws://cdn.example.test:443/`) it tunnels as `wss` does and passes (corrected 2026-10-02, #43).
  - `connect` names its requester: `request` for a plain request, `tunnel` for a `CONNECT` and `runner` for a runner-side request, which passes for an allowed origin only, never a subresource host. So every allowlist decision stays in `EgressPolicy`.
  - Anything else is refused and recorded before any lookup.
- **IP policy, local and CI runs.**
  - *Always refused:*
    - link-local addresses, IPv4 and IPv6, which covers 169.254.169.254 and ECS's 169.254.170.2;
    - unspecified addresses;
    - the metadata and credential services outside link-local: `fd00:ec2::/32` (AWS's instance metadata and EKS Pod Identity over IPv6), `fd20:ce::254` (GCP's on IPv6-only VMs), `fd00:c1::a9fe:a9fe` (OCI's), `100.100.100.200` (Alibaba Cloud's) and `168.63.129.16` (Azure's WireServer, a public address);
    - NAT64's local-use prefix `64:ff9b:1::/48` (RFC 8215), whose embedded IPv4 address can't be read back without the prefix length.
  - *Embedded IPv4:* an IPv6 form that embeds an IPv4 address is judged as that address: IPv4-mapped, IPv4-translated (`::ffff:0:0:0/96`, RFC 2765), IPv4-compatible, NAT64's well-known prefix (`64:ff9b::/96`) and 6to4. Python 3.14 calls `::7f00:1`, `::ffff:0:7f00:1` and `64:ff9b::a9fe:a9fe` global, though they reach 127.0.0.1 and 169.254.169.254. Refusing those ranges outright would break DNS64 networks, where an IPv6-only host gets `64:ff9b::` answers for IPv4-only sites.
  - *Public* means Python's `is_global`, from IANA's special-purpose registries, less multicast, and for IPv6 also inside `2000::/3`, the only space allocated for public unicast: Python calls multicast and IPv6's site-local `fec0::/10` global. Any other address (loopback, RFC 1918, unique-local, the shared 100.64.0.0/10) passes only for the host and port of the start origin or a declared private origin. Declaring a private origin lets an allowed origin or a subresource host resolve to a private address; it doesn't make the origin reachable.
  - *Residual:* Teredo addresses (`2001::/32`) aren't unpacked. Python calls them non-public, so only a declared private origin could resolve to one, and reaching it needs a Teredo interface. Nor are NAT64's network-specific prefixes (RFC 6052), which an operator chooses inside `2000::/3`, so they count as public: an address there could reach a private IPv4 address only on an IPv6-only network whose DNS64 uses such a prefix, for an allowed host whose DNS an attacker controls. AWS's and GCP's DNS64 use the well-known prefix, which is unpacked.
  - *Matched by host and port:* a request's scheme isn't known at `CONNECT`, so the policy never compares schemes (see *Which hosts pass*). A runner-side request names its scheme, so its whole origin is checked before the policy sees it (see *Runner-side requests*).
- **DNS pins.**
  - *The resolver is a seam:* `EgressGate` takes a `resolve` function (`aqa_runner.egress.Resolve`). A run uses `system_resolve`, the event loop's `getaddrinfo`. The local DNS fixture is a scripted resolver the tests inject (`ScriptedResolver` in `packages/runner/tests/test_egress.py`, and a smaller `Resolver` in `test_egress_proxy.py`), which changes its answers mid-run and counts lookups. *Rejected:* a DNS server on loopback, which would need a DNS client library in the runner only so tests could point it there.
  - *Pinned for the run:* a name's first answer whose every address passes the IP policy is pinned for the gate's life, and one gate serves a whole run, every browser session and runner-side request in it. A pinned name is never looked up again. An answer with any refused address is refused and isn't pinned. Lookups of one name take turns, so two first requests pin one answer. A connection that has no answer for its host within 10 seconds, whether it looks the name up or waits behind another connection's lookup, is an infrastructure event, and nothing is pinned.
  - *Judged per connection:* a pinned answer is checked again for each host and port, since whether a private address may pass depends on the port as well.
  - Connections go to the pinned addresses in the answer's order, and the first that accepts within 10 seconds is used, so an address that drops packets can't hold up the rest for the OS's own timeout. An address written as the host is never looked up.
  - *Residual:* there's no Happy Eyeballs behind the proxy. While a pinned address drops packets, every connection to its host waits those 10 seconds before trying the next address, for the rest of the run.
- **Records.**
  - `refusals` give the host, the port, the kind and why. Kind `host` is a host outside the allowlist, an egress block unless the project expects it; what it does to the run is #47's. Kind `address` is the IP policy.
  - `infrastructure_events` record a name that doesn't resolve and an answer with no address that accepts. `EgressUpstreamError` is an infrastructure error (API.md §7, 10+). Its code, and how a run reports an unreachable start origin, are #46's and #53's.
- **The proxy server** (`aqa_runner.egress_proxy.EgressProxy`) serves on 127.0.0.1 for the run, holding the run's gate, and every browser session goes through it: `open_browser_session` takes a required `egress`. Both sides of an exchange are framed by `aqa_runner.egress_peers`, which runner-side requests share.
  - *One request per browser connection.* h11 frames HTTP/1.1. Every plain response says `Connection: close`, because Chromium answers a failure on a reused connection by sending the request again, POSTs included, which would repeat a side effect. Each request asks the gate, and goes upstream with `Connection: close`, the target's own `Host` and its target as the page wrote it. Hop-by-hop headers, `Upgrade` among them, and any header `Connection` names stay behind: Chromium opens WebSockets through `CONNECT`. A request framed both ways goes upstream with `Transfer-Encoding` only (RFC 9112 §6.3).
  - *Every host the page names is judged.* A host written another way than an origin writes it (a trailing dot, an IPv4-mapped literal, port 0) reaches the gate, which refuses and records it; letter case and a port's leading zeros are read as an origin reads them. Only a request no browser sends (a relative or https target, a user, brackets that don't close or that hold a name) is dropped unread.
  - *The proxy is set per browser context.* The session passes `proxy` to the one context it creates, with the bypass list `<-loopback>`, so loopback traffic goes through the proxy too. Playwright adds `<-loopback>` itself unless `PLAYWRIGHT_DISABLE_FORCED_CHROMIUM_PROXIED_LOOPBACK` is set in its driver's environment, which inherits the runner's; passing it explicitly makes that variable irrelevant. *Not the main mechanism:* `--proxy-server` at launch, which would give `launch` an option. A context created anywhere else has no proxy, though, so #43, which changes the launch for WebRTC and QUIC anyway, adds a launch-level proxy as a second layer.
  - *Refusals never look like the app's response.* A refused `CONNECT` gets 403 and a failed one 502, which fails the tunnel; Chromium never shows a page a proxy's `CONNECT` response. A refused or failed plain request has its connection closed with nothing sent, which the page sees as `net::ERR_EMPTY_RESPONSE`: a synthesized 403 or 502 would reach the page as the app's response. Any failure on the upstream side, in a plain exchange or a tunnel, drops the browser's connection too and is an infrastructure event; one on the browser's side, such as a closed tab, isn't. A browser that aborts a request lets the upstream go rather than holding it until it answers, and closing the proxy ends every request still in it.
  - *Residual:* a request body goes upstream in full before the response is read, so an upstream that answers early (413 to a large upload) and stops reading holds the exchange; a follow-up forwards both at once.
  - *No way around it.* With the proxy gone, Chromium fails the request (`net::ERR_PROXY_CONNECTION_FAILED`) rather than connecting directly; the session's tests show it, with loopback, and with Playwright's opt-out variable set.
  - *Our own asyncio proxy, framed with h11.* *Rejected:* mitmproxy, which intercepts TLS, as we never do; proxy.py, which resolves names itself, so nothing could pin them; and a sidecar binary.
- **Runner-side requests** (`aqa_runner.runner_requests.runner_request`): the reset hook's and probes' own requests (#56, #48), which take a method (GET or POST) and an absolute URL. They're a caller of the gate, not of the proxy.
  - *Same rules:* they connect through the gate's `connect` as the `runner` requester, so they reach allowed origins only, under the run's DNS pins and IP policy, and the gate records their refusals and failures. A URL whose origin isn't one, or whose path and query no request line can carry, raises `ValueError` before any connection.
  - *Matched by the whole origin.* An origin is its scheme, host and port, and a runner-side request names all three, so before it asks the gate, its URL's origin, read as `aqa_core.schema.parse_origin` reads every origin, must be exactly one of the run's allowed origins. An `http` URL on an allowed `https` origin's host and port is refused and recorded with the gate (kind `host`) before any lookup, and so is the reverse: a reset hook, which may carry credentials, never goes out in plaintext to a port the project declared for TLS. The gate's host-and-port check stays as the second layer, and `EgressPolicy` is unchanged. *Rejected:* host and port only, as the browser's traffic is judged: #42's Codex adversarial review showed an `http` reset POST going out in plaintext, unrecorded, to an origin allowed only over `https`.
  - *Nothing of the browser's:* a request sends only `Host`, `Connection: close` and, for a POST, `Content-Length: 0`. There's no cookie jar, so no request carries the browser's cookies or one an earlier runner-side response set.
  - *Redirects come back unfollowed*, as the response: following one would need a check per hop for no current need, and the caller decides what a 3xx means.
  - *HTTPS from the first byte.* For an https URL the request passes the gate a TLS context, `ssl.create_default_context()`, and the gate opens its connection to the pinned address with TLS (`asyncio.open_connection` with `ssl` and the host as `server_hostname`), so the certificate is checked against the URL's host and nothing resolves it again. The handshake is part of connecting: it's under the gate's 10-second connect timeout, and an address whose certificate doesn't verify fails like one that doesn't answer, so the answer's next address is tried and, when none succeeds, it's an infrastructure event. The proxy passes no context: it never terminates TLS. *Rejected:* upgrading the gate's plain connection in place (`StreamWriter.start_tls`). Bytes a server sends before the handshake would stay in the stream's buffer and be read as if they had come over TLS, so an on-path attacker without the certificate could answer a probe or a reset; only asyncio's scheduling keeps them out, while nothing awaits between connecting and upgrading (#42's final security review showed it with one `await` added).
  - *No deadline of its own* past the gate's for connecting: a caller bounds a request with `asyncio.timeout`, as #48's probe reads and #56's reset are to, and the request's connection closes when the deadline cancels it. A deadline that passes that way isn't one of the gate's records. *Residual:* a caller may cap a response body's size (`limit`, the #53 P20 amendment); exploring's probe capture does, and stable probe reads and the reset hook don't.

## Amendment (2026-10-01): secret bindings on the loaded spec (#88)

`aqa_core.project.secret_destinations` took a spec and a project config, and looked up each secret the spec references in that config. That was right only for the config the spec was loaded with: handed another, it raised a raw `KeyError` instead of a `SpecError` (#39's final review).

- **A loaded spec carries its bindings.** `load_spec` and `load_project` give each spec the bindings of exactly the secrets it references, from the config whose secrets they just checked its references against (`Spec.secret_bindings`). `secret_destinations(spec, start)` takes no config, so it can't be handed the wrong one. `load_project` builds a spec only when the config is valid, since an invalid config has no bindings to give.
- **The seam for `fill_secret` (#49)** is `secret_destinations(spec, start)`. `fill_secret` must not read `Spec.secret_bindings` directly: there `start` is unresolved, and nothing has checked the bound origins against the run's allowed origins.
- **`Spec` holds the rule itself.** However a `Spec` is made (by a loader, by hand, or with `dataclasses.replace`), it keeps its own copy of the bindings, and it raises `ValueError` unless they are the bindings of exactly the secrets its frontmatter references. So no `Spec` can bring the `KeyError` back, and a later change to the mapping it was given, or to the config's, doesn't reach it. The copy is a plain dict behind the read-only `Mapping` type, which mypy enforces; a `MappingProxyType` would make a `Spec` fail `copy.deepcopy` and `pickle`.
- **`Spec`'s constructor stays public:** hosted runs will take bindings from the test-secrets API, not a config (DATA_MODEL §9).
- **Bindings aren't part of `spec_hash`,** which covers the frontmatter as written (DATA_MODEL §7). Changing a binding in the config makes no compiled script stale, as before.
- *Rejected:* each secret reference in the frontmatter carrying its own binding, filled in during validation. That puts config data into the model of the spec as written, and `load_project`'s invalid-config path has no binding to fill, so the binding becomes optional where the loader rules that out.
- *Residual risk:* `Spec` checks the bindings' names, not where they came from. A `Spec` assembled by hand can pair a spec's references with bindings no loader gave it: another spec's frontmatter swapped in with `dataclasses.replace`, or bindings for the same names taken from another config. No production code builds a `Spec` that way. `tests/test_start_url.py` replaces a spec's preconditions; its template references no secret, so the names still match, and a template that did would now raise `ValueError`. Only a private constructor would close this, and hosted runs need the public one.

## Amendment (2026-10-02): the other ways out, closed at launch (#43)

The egress proxy is set on the session's own context (the #42 amendment), so the Decision's "Other transports" (no UDP past the proxy) and a context created anywhere else were still open. `aqa_runner.sandbox.launch_with_observations` now passes every launch two things, in its one `chromium.launch` call: the transport switches (`TRANSPORT_SWITCHES`) and a fail-closed launch-level proxy (`FAIL_CLOSED_PROXY`). The `Chromium` protocol takes `args` and `proxy` for them, as it took `env`. `launch` still takes no option and reads no setting, and the sandbox check is unchanged.

- **The switches.** Playwright appends them after its own ([`args`](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-option-args)).
  - `--force-webrtc-ip-handling-policy=disable_non_proxied_udp` and `--webrtc-ip-handling-policy=disable_non_proxied_udp`: WebRTC "should only use TCP to contact peers or servers unless the proxy server supports UDP" (Chromium's `kWebRTCIPHandlingDisableNonProxiedUdp`), and an HTTP proxy carries none. The headless shell, which Playwright runs when headless, reads only the first (`headless/lib/browser/headless_web_contents_impl.cc`). Full Chromium, which Playwright runs headed (as `PWDEBUG` forces) or by `channel`, reads only the second, into its WebRTC preference (`chrome/browser/prefs/chrome_command_line_pref_store.cc`); each ignores the other's. CI installs only the headless shell, so the full binary's behaviour is unproven by our tests. Measured on macOS: no ICE candidate and no datagram to a STUN server on a loopback UDP canary; without the switch, an mDNS host candidate, and the STUN requests reached the canary past the proxy.
  - `--disable-quic`: "Disables the QUIC protocol" (Chromium's `network_switch_list.h`). QUIC runs over UDP. It is a second layer no test here can see: every context now has a proxy, and with any proxy but a direct one WebTransport fails before it sends (`DedicatedWebTransportHttp3Client::DoCheckProxyComplete`) and Chromium sends HTTP/3 through no HTTP proxy. The command-line test pins it.
  - `--host-resolver-rules=MAP * ^NOTFOUND, EXCLUDE 127.0.0.1`: the browser resolves no name itself, so DNS prefetch, a STUN server's name or any other lookup of its own can't send a DNS query; every name is the egress proxy's to resolve and pin. `^NOTFOUND` is Chromium's sentinel (`net/dns/mapped_host_resolver.cc`): its host-and-port path fails a lookup only for exactly that host, so `~NOTFOUND`, a form often quoted, would be looked up there as a name (LAB_NOTES, 2026-10-02). The rule maps address literals as well, so it spares `127.0.0.1`, the address `EgressProxy` listens on; measured, without the exclusion the session's own proxy fails (`ERR_PROXY_CONNECTION_FAILED`).
  - *Not used:* `--disable-features`. Playwright passes its own list, and Chromium keeps a switch's last value, so a second one would replace Playwright's. (Superseded: the amendment on WebRTC's mDNS responder, below, adds one that repeats Playwright's list.)
- **The fail-closed launch-level proxy.** `http://launch-proxy.invalid:1` with the bypass list `<-loopback>` ([`proxy`](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-option-proxy)). Every context that names no proxy of its own gets it (but see *Residual risk* on `client_certificates`): the sandbox check's blank page, and any context opened outside the browser session. `.invalid` never resolves (RFC 6761), and the resolver rule stops Chromium's lookup before any query leaves, so every request such a context's pages make fails with `ERR_PROXY_CONNECTION_FAILED`, loopback included. The session's context names the run's egress proxy, which Chromium uses instead.
  - *Rejected:* the run's egress proxy at launch. `launch` would take an option, the sandbox module would depend on the egress proxy, every caller (the spike's trial, the time-zone tests) would need one, and a stray context would reach the allowed hosts rather than nothing. *Rejected too:* an unused loopback port, which a local process could bind.
- **Tests.** `packages/runner/tests/test_transports.py` runs each check twice: as `launch` launches, and as a control launched through `launch`, sandbox check included, by a `Chromium` double that leaves out the switches and the launch-level proxy.
  - The browser process's command line carries each switch and the proxy; the control's carries none of them, and leaves out exactly what `launch` asked for.
  - WebRTC with a STUN server on a UDP canary gathers no candidate and sends nothing; the control's datagrams reach the canary.
  - A context naming its proxy `localhost` fails while the session loads through `127.0.0.1`; the control's loads through either. Chromium answers `localhost` itself, so this shows the rule failing a context's lookups, not a query that would have left; removing the exclusion breaks the session, which pins the rule to `EgressProxy`'s address.
  - A context opened with no proxy fails, and the origin sees nothing; the control's loads the page directly. It runs again with `PLAYWRIGHT_DISABLE_FORCED_CHROMIUM_PROXIED_LOOPBACK` set, where only the launch proxy's own `<-loopback>` keeps loopback behind it.
  - The test doubles in `test_sandbox.py`, `test_browser_session.py` and the spike's `test_trial.py` take the two new keywords and pass them on; their assertions are unchanged.
- **Residual risk.**
  - Code that names a proxy for its own context gets that proxy: the launch-level proxy catches a context that forgets one, not one that chooses another. So does code that passes Playwright's `client_certificates` to a context: Playwright then gives the context a SOCKS proxy of its own in its driver, which connects from Node through the context's own proxy if it names one, and otherwise straight to the host (or through the runner's `HTTPS_PROXY`), past the launch proxy and the resolver rule. No code does either today; review catches it, as for the spellings `tests/test_chromium_launches.py` can't see.
  - The resolver rule binds Chromium only. A stray context's `context.request` goes out from Playwright's driver to the launch proxy, so Node's resolver looks up `launch-proxy.invalid`, which fails: a query leaves, nothing else does. Chromium's secure-DNS probes (`MappedHostResolver::CreateDohProbeRequest`) skip the rule; the headless shell configures no secure DNS, which the packet-level suite will show, and full Chromium, which may default to automatic secure DNS, is unproven here too.
  - Proving that nothing leaves at the packet level, QUIC and DNS included, is the hostile-page suite's (#43's later change). On macOS these tests observe what reaches the canaries and the origin, not packets.
- **Still to come in #43:** the hostile-page suite observed at the packet level. Routing, blocked service workers and popups have an amendment of their own below.

## Amendment (2026-10-02): document origins (#44)

The Decision's check before every observation and action lives in the browser session (`aqa_runner.browser_session.BrowserSession`), so the navigator's tools (#53) and the executor (#46) both get it. This amendment covers what the session observes (`snapshot`, `locate`) and popups. Its actions and `navigate` follow in a second change, which amends this section.

- **One allowlist.** The session reads the run's `EgressPolicy` from the egress proxy (`EgressProxy.policy`). A document is allowed when its origin is one of the policy's `allowed_origins`, scheme included. Subresource hosts are never consulted, so a subresource host that becomes a document gains no authority.
- **A document's origin** comes from the URL Chromium reports for its frame ([`frame.url`](https://playwright.dev/python/docs/api/class-frame#frame-url)), which page scripts can't forge (`aqa_runner.document_origins.document_origin`):
  - an http(s) URL's origin, written as `parse_origin` writes it, without a user or password;
  - a `blob:` URL's inner origin;
  - for `about:srcdoc`, its parent frame's: only the parent's `srcdoc` attribute makes one, and Chromium refuses a navigation to it;
  - for `about:blank`, its parent frame's only when the parent can reach its document (its owner's `contentDocument` is a document, evaluated in the parent's world; an `<embed>` has none, so its frame never counts as reached). A document reached by navigating to about:blank takes the origin of the frame that navigated it there, not its parent's: only the initial empty document inherits the parent's (HTML's "determining the origin"; reproduced on Playwright 1.63's Chromium, and pinned by `test_a_blank_frame_another_origin_wrote_is_left_out`). So a subresource host's frame can navigate a sibling frame on its own origin to about:blank and write into it, and the reach check, the browser's own same-origin check, is the one that host can't answer for the parent (`aqa_runner.document_origins.frame_origin`). A top-level about:blank, the session's blank first page or a blank popup, is on none;
  - none for anything else: `data:`, Chromium's error page (`chrome-error://chromewebdata/`, what the browser shows after the proxy refuses a host), `file:`.

  So the session's blank first page, an error page and a `data:` frame are on no allowed origin, even when an allowed page made the `data:` frame. A blank frame that the app's own script wrote is on the app's origin. A sandboxed frame at an allowed URL counts as that origin: its content came from the allowed server.
  - *Rejected:* CDP's `securityOrigin` for each frame, which is exact but needs a CDP session per out-of-process frame; the frame's own `self.origin`, which the frame's scripts can replace, and a subresource host writes a relabelled blank frame's; and leaving out every blank frame, which would hide frames that apps build by script, such as rich-text editors.
- **The check.** Before every snapshot and every ref lookup, the session's top-level page must be on an allowed origin, and the element a ref lookup finds must be in a frame on one. Otherwise the session records a **policy event** (CONTEXT.md) and raises `PolicyEventError`. The error's message names the origin only, never the URL, whose path and query the page chose. Nothing is returned, so nothing there is observed, and the refs of the last snapshot stay retired. The check reads the page's current URL each time, so after navigating back to an allowed origin, observing works again.
- **Frames in a snapshot.** Playwright's AI snapshot adds each frame's content below its iframe's line, cross-origin frames included: it gives `<iframe>` and `<frame>` elements the role `iframe` and stitches only below those (1.63's `mergeIframeChildren`).
  - The session resolves each iframe's ref to its content frame, as Playwright does, and leaves out the content of every frame that isn't on an allowed origin, nested frames below it included. The iframe's own line stays, with `LEFT_OUT` in place of its ref.
  - An element that *contains* such a frame (a region around it, or a kept iframe with one nested inside) keeps its ref, and a click on it lands in the frame: Playwright's hit-target check accepts the target or any descendant, and every point over an `<iframe>` hits the `<iframe>` element. So the actions' change refuses to act on an element that contains a frame on no allowed origin; until then nothing in the session acts.
  - *Reading of the criterion "A cross-origin iframe's content can't be observed or acted on":* a frame on **another allowed origin** stays observable, as the issue's rule says ("the top-level page's origin and the target frame's origin must be allowed origins"). Only frames on origins the run doesn't allow are left out. The tests keep a frame on a second allowed origin as a control.
  - Leaving a frame out is not a policy event. An allowed page that embeds a third-party frame, such as an ad or a widget, reached nothing, and an event for each would fire on any such page. Acting into such a frame is refused with a policy event (the actions' change).
  - *Rejected:* a snapshot per frame, which needs Playwright's frame numbers that the Python API doesn't expose; and refusing any page that embeds another origin's frame.
- **A snapshot raced by a frame change is discarded.** A frame could show another origin's document while Playwright takes the snapshot, then move to an allowed origin before the session reads where it is, and its content would pass. The session counts every [`framenavigated`](https://playwright.dev/python/docs/api/class-page#page-event-frame-navigated) on its page, same-document ones included, and every `framedetached`. If any frame navigates or is removed between the page's check and the last frame's, `snapshot` raises `DocumentChangedError` and the caller takes another. Same-document navigations count too, so a page that updates its history during a snapshot makes the caller observe again; the navigator (#53) bounds those retries. A removed frame's content can't be checked any more, and resolving the ref of a frame nested in it raises Playwright's "Invalid frame in aria-ref selector", which the session reports as the same change. Playwright reports a navigation before the result of anything that ran in the new document. With no change, the page is the document its check saw, so the page needs no second check. *Rejected:* retrying inside `snapshot`, which a page that keeps navigating would hold in a loop.
- **Ref lookups** check the top-level page, then the frame of the element they find (a policy event of kind `frame`); an element of a document no frame shows is refused as gone (`RefError`). A ref names only an element the current snapshot showed, which a left-out frame's never are, and the element `locate` returns is held: it can't act in a later document. So the frame check is defense in depth, for a ref Playwright might resolve elsewhere; the tests reach it by injecting that fault.
- **Popups.** The session listens for every page opened in its context ([`page`](https://playwright.dev/python/docs/api/class-browsercontext#browser-context-event-page)), popups of popups included. It records each in `popups` as a `Popup` with its first URL and its opener's URL, then closes it. Playwright reports the popup once it has navigated to its first URL, and reports the opener even for a `noopener` link, but not once the opener has closed. A popup on no allowed origin is also a policy event, of kind `popup`, and so is a blank popup: Playwright names the page that opened it, not the frame, which may be a subresource host's. That makes an app's own `window.open()` followed by a navigation (an OAuth, payment or print flow) a policy event too, a false positive #47 has to weigh before a popup event ends a run; CDP's `securityOrigin` for the popup can't tell the opening frame either. The session never observes a popup. The records fill as Playwright reports popups, which can be after the call that opened one has returned.
- **Policy events** are `PolicyEvent(kind, url, origin)`: `kind` is `document` (the top-level page), `frame` (the frame of an element the session was about to give out) or `popup`. `url` is as Chromium reports it, and redacting it before it is saved is #50's. `origin` is None when the document has none. What a policy event does to the run is #47's.
- **Bounded records.** `policy_events` and `popups` keep their first 100 entries and count all of them (`Records`). Playwright launches Chromium with popup blocking off (`--disable-popup-blocking`), so a page can open popups in a loop. The first entries show what started it.
- **The page stays public** until #53 makes it private (the owner's comment on #44). No production code outside `browser_session.py` may use `BrowserSession.page`: it observes and acts without the checks.
- **Residual risk.**
  - The check trusts that Playwright reports a frame's navigation before the result of a snapshot taken in its new document, which holds for 1.63's protocol order.
  - A popup whose first navigation never commits (its server accepts the request and withholds the response) isn't reported by Playwright, so it stays open and unrecorded until it commits. It is never observed, but a page can open many. Closing popups as their targets appear, through the browser's CDP target events, is a follow-up.
  - The reach check trusts the parent's world, which the allowed page's own scripts, a subresource host's script it loads among them, already control.

## Amendment (2026-10-02): routing, service workers and popups (#43)

The browser session's second layer, behind the egress proxy and the launch's switches (the 2026-10-02 amendment on the launch). `open_browser_session` blocks service workers and installs routing on its context before the first page exists. `aqa_runner.routing` holds the routing.

- **Routing aborts and records; the proxy stays the enforcer.** `install_routes` adds `context.route("**/*")`, and `context.route_web_socket` with a pattern of the sockets the policy refuses ([route](https://playwright.dev/python/docs/api/class-browsercontext#browser-context-route), [route_web_socket](https://playwright.dev/python/docs/api/class-browsercontext#browser-context-route-web-socket)). Each request and routed socket is judged by `refused_attempt` against the run's `EgressPolicy`, which `EgressProxy.policy` exposes read-only, so the allowlist is never copied. Chromium routes no `data:`, `blob:` or `about:` request, which reach no network.
  - *Read as the proxy reads it:* the host and port come from `aqa_core.schema.authority`. A plain `http` request is the proxy's `request` requester; `https`, `ws` and `wss` are `tunnel`, since Chromium tunnels all three through `CONNECT`. A URL's user part is ignored, because Chromium leaves it out of the request line (`HttpUtil::SpecForRequest`). Any other scheme is refused, since the proxy carries nothing for it, and so is a URL no browser writes.
  - *A refused request* is aborted (`blockedbyclient`, so the page sees `net::ERR_BLOCKED_BY_CLIENT`) and recorded. Any other request goes on to the proxy, which judges it again, every redirect hop included.
  - *A refused socket* is closed and recorded. Routing takes only those: `refused_sockets` builds, from the same policy, a pattern that matches a socket URL, as WHATWG URL serializes it, exactly when the policy refuses its host and port, and Playwright matches it before it routes. Every other socket stays the page's own and goes to the proxy. *Why not every socket:* Playwright 1.63's forwarding of a routed socket converts a Blob with an asynchronous `arrayBuffer()` and sends a string at once, so a page that sent a Blob and then a string had them arrive reversed (measured, with the Blob lost when the page closed at once); a socket no pattern matches is passed through natively and keeps its order (measured). The two readings of the policy are pinned against each other by `test_routing.py`'s socket verdicts.
  - *Socket routing is best effort against a hostile page.* It runs in Playwright's wrapper inside the page, which a page can go around: a `WebSocketStream`, which Playwright doesn't wrap; a socket whose writable `url` the page rewrites before Playwright's passthrough reads it; or the wrapper's own methods, called directly. Each such socket reaches the proxy, which refuses it and records it among the gate's refusals, so a refused socket can appear in either record, or both.
  - *Options:*
    1. aborting and recording (chosen by the maintainer, 2026-10-02): the defense in depth SECURITY §7 names;
    2. recording only, with every request passed on to the proxy (rejected): one enforcer, which keeps every browser test showing the proxy's own refusal, but not the second layer SECURITY §7 and this ADR describe;
    3. passive request and WebSocket events instead of routes (rejected): this keeps the HTTP cache and even sees redirect hops, but enforces nothing and isn't the routing SECURITY §7 names.
- **Records.**
  - `BlockedAttempt` keeps Playwright's resource type (`websocket` for a socket), the scheme, the host and the port. It never keeps the path, the query or the user part, which a page can fill with what it exfiltrates. The host is kept only when an origin could write it and it is at most 253 characters (otherwise it is empty), and even then a page chooses it, so the redaction that runs before anything is saved must cover it, in the gate's refusals as well (#50; corrected 2026-10-02 by #49, which this line first named).
  - `BlockedAttempts` keeps each distinct attempt, the first 1000 of them, with how many times it was made, and counts all attempts. A page that loops on one blocked request takes one place, and the record can't grow without bound. A page can still choose a thousand distinct attempts (one host, many ports) and fill it: an attempt after that is counted but not named, and `overflowed` says so. Both types live in `aqa_runner.egress_proxy`, and the record on the run's egress proxy (`EgressProxy.blocked_attempts`), beside the gate's `refusals`.
  - *Egress blocks are in both records.* Routing now refuses most requests to an undeclared host before the gate sees them: the gate's refusals hold only what routing can't see (redirect hops, dedicated workers' sockets). So an egress block (#47) is a `host` refusal in either record, and #47 reads both, without assuming they never overlap (see *Socket routing is best effort*), and counts an `overflowed` record as an egress block, since it names not every refused host. #47 also decides whether a refused scheme the proxy carries nothing for counts, and its expected-blocked matching must accept routing's `net::ERR_BLOCKED_BY_CLIENT` as well as the proxy's failures.
  - Persisting both in the run's record is #46's and #53's.
- **Consequences.**
  - *No HTTP cache.* Playwright 1.63 turns Chromium's cache off whenever routing intercepts requests (it sends `Network.setCacheDisabled`). So every session runs without one, and a repeat fetch reaches the server. `test_two_sessions_share_no_profile_storage_or_cache` now asserts that (approved by the maintainer, 2026-10-02).
  - *Every request costs a round trip* to the runner's route handler before it leaves.
  - *A socket routing blocks closes cleanly:* the page sees `close` (code 0, or 1006 if one is passed, with `wasClean` true either way) and never `error`. A refused connection otherwise fires `error`, then `close` with 1006 and `wasClean` false. No Playwright 1.63 API fires `error` from a route, so app code that handles only `onerror` behaves differently under routing than under a proxy refusal. This was measured.
  - *`route_web_socket` doesn't cover dedicated workers.* Playwright's WebSocket routing runs in frames, so the proxy is a worker's sockets' only layer. Measured: a worker's socket to a disallowed host reaches the proxy, which refuses it.
  - *Two proxy-session tests now show the proxy's own refusal where routing can't act* (approved by the maintainer, 2026-10-02):
    - The loopback test reaches `127.0.0.1` and `localhost` through redirect hops, and its direct loads are aborted and recorded by routing.
    - The WebSocket test opens the disallowed socket from a dedicated worker, and the page's own socket is aborted and recorded.
- **Service workers.**
  - *Playwright's own block isn't enough.* `service_workers="block"` ([option](https://playwright.dev/python/docs/api/class-browser#browser-new-context-option-service-workers)) is an init script that replaces only the instance's `navigator.serviceWorker.register`, with one that resolves. Measured: calling the prototype's method, deleting the replacement, and registering from a same-origin iframe each registered a worker anyway.
  - *The session adds a lock.* `SERVICE_WORKERS_REFUSED`, a context init script, defines `register` on `ServiceWorkerContainer.prototype` and on the instance as non-writable and non-configurable, rejecting with `SecurityError`. Each of the eight ways the test tries (the plain call, the prototype's method, either after assigning a replacement, after deleting the instance's, from a blank and a same-origin iframe, and from a popup) is refused with `SecurityError`, nothing is registered, and the worker script is never requested; a control context that allows service workers registers one. A dedicated worker has no `navigator.serviceWorker` in Chromium 153 (measured).
  - *Residual:* a realm whose scripts run before Chromium injects init scripts. A worker registered that way would still send every request through the context's proxy.
- **Popups** meet the context's routes and its proxy while they are open: a popup sent straight to a disallowed host is aborted and recorded by routing, and one that gets there by a redirect is refused by the proxy. The session records and closes every popup (the amendment above, #44).
- **Still to come in #43:** the hostile pages and their tests, which observe packets as the next amendment describes.

## Amendment (2026-10-02): observing packets (#43)

The Decision's egress tests are "observed at the packet level" (Other transports; TESTING §1). `tests/packet_capture.py` does that on Linux, as CI runs it, without root and with the standard library only; the hostile pages that use it follow.

- **How.** `observe(scenario, name)` runs an async scenario in a child process (`python -m tests.packet_capture`, from the repository's root). On Linux the child first enters a network of its own (`tests/capture_network.py`), a user, network and mount namespace:
  1. Mapped to root inside it, it brings `lo` up and adds local routes for `0.0.0.0/0` and `::/0` (`ip route add local … dev lo table local`, over rtnetlink), so every address is local and a packet to any address, a DNS server's included, is sent and seen instead of failing for want of a route.
  2. It adds a veth pair with an IPv4 address and no IPv6 one. WebRTC never gathers on `lo`, so without it a browser leaks nothing even with its switches off (measured); an IPv6 address would make the kernel send router solicitations and duplicate-address checks of its own. A multicast packet, such as mDNS, goes out the veth.
  3. It puts an empty tmpfs over the host's resolver daemons' socket directories (`/run/systemd/resolve`, `/run/nscd`, `/run/avahi-daemon`, `/run/dbus`), in its own mount namespace only. Through nss-resolve, nscd or nss-mdns a lookup would reach a daemon that sends the query from the host's network, past the capture; hidden, glibc falls back to DNS from inside the namespace (Codex's review). A host whose `hosts:` line in `nsswitch.conf` names any other source (sss, ldap, wins…) is refused, since its daemon would stay in reach. The hiding is a snapshot: a daemon directory made later on the host's `/run` would show.
  4. It opens an `AF_PACKET` socket on every interface with a `TPACKET_V2` receive ring of 64 MiB in 512-byte frames, which keep a packet's headers, then drops to its own uid in a nested user namespace, because Chromium won't sandbox as root; the socket and ring stay open across it.
  5. It runs the scenario, browser, egress proxy and fixture servers included, drains the ring, and reports each flow of IPv4 and IPv6 packets any interface sent: protocol, addresses and ports, past IPv6 extension headers, with no ports for a later fragment or a frame cut short (`tests/packet_flows.py`). Other frames, such as ARP, aren't flows.
- **An incomplete capture is never evidence.** The child fails if the kernel dropped a packet (`PACKET_STATISTICS`) or the reader raised anything. A plain `AF_PACKET` socket, drained by a Python thread, dropped packets under load: about 1,900 in a 20 MB loopback transfer, losing some of 200 marker datagrams (the security review's measurement). Its buffer can't grow (`SO_RCVBUFFORCE` needs `CAP_NET_ADMIN` in the host's namespace); the ring lost none at 20 MB, and a control checks that.
- **What it needs.** Unprivileged user namespaces, as Chromium's sandbox does: CI's `python` job relaxes AppArmor's restriction before `uv run pytest --cov` (the 2026-09-30 amendment), so no workflow, script or tool changes. The veth driver, as a module the kernel loads when the link is created or built in (it worked so in an `ubuntu:24.04` container on Docker Desktop's 6.12 kernel; CI's runner is the authority). A machine that keeps the restriction must give the workspace's Python an AppArmor profile that allows user namespaces too, not only Chromium.
- **Controls** (`tests/test_packet_capture.py`, scenarios in `tests/capture_scenarios.py`; the parsing in `tests/test_packet_flows.py`):
  - an IPv4 and an IPv6 datagram to addresses nothing routes, and a name lookup through the system resolver, all appear, and nothing else does but the ICMP errors that answer them, so the namespace is quiet but for what a scenario sends;
  - a session launched without the transport switches and the launch-level proxy (`test_transports.py`'s control) leaks its STUN request, which the capture sees;
  - a 20 MB loopback transfer with 200 marker datagrams interleaved: every marker appears, and nothing is dropped;
  - a reader that raises anything, or a kernel that drops a packet, fails the capture.
- **macOS.** Nothing captures without root there (BPF devices are root's), so a scenario runs in the child as it is and `flows` is None. There the first control checks only that its scenario runs, the second that its session gathers WebRTC candidates, the leak the capture must see on Linux, and the third that the transfer completes; the parsing and the failure checks run everywhere. The hostile pages check destinations there (canaries, the origin, the gate's records), and packets only on Linux, in `sys.platform` branches with no skip markers. CI is the gate.
- *Rejected:* `tcpdump` under `sudo` in CI, which needs root, a workflow change and a tool, and can't run on macOS; Playwright's Docker image with a capture inside, a pinned image and a seccomp profile to maintain, and slow; Chromium's NetLog, which is the browser's own account of its traffic, not packets.
- *Residual:* packets name addresses and ports, not processes. They prove that nothing reached a disallowed host. They can't tell a browser that connected straight to an allowed origin from the egress proxy's own upstream connection to it: both are loopback to the origin's port, and the routes make a packet's source its destination. The hostile pages need a control of their own for that half of "bypasses the proxy", such as matching every connection the origin accepts to the proxy's.

## Amendment (2026-10-02): document origins, actions and navigation (#44)

The second change of #44 gives the browser session the surface that #46's executor and #53's tools act and observe through. It completes the amendment on document origins above, and supersedes its "until then nothing in the session acts".

- **The surface,** agreed with #46. Each method is async, takes the session's lock, and checks before it does anything. A refusal records a policy event and raises `PolicyEventError`.
  - `navigate(url)` and `reload()`.
  - `click(element)`, `fill(element, value)`, `select(element, option)` and `press(key)`. Each action returns its settle window, and #46 adds `settle(window)`, `text_of(element)` and `visible_text()`, which check the page as every observation does (ADR-0024's amendment, Settling and Reading text). An element comes from `locate(ref)` (the navigator's) or `resolve(target, use)` (the executor's), so both reach the same checks. `select` takes the option whose value or label is `option` (Playwright's `select_option` with a string).
  - `resolve(target, use)`, which wraps `aqa_runner.locators.resolve` and keeps its overloads.
  - `url()`, a method because it takes the lock and checks the page. `snapshot()` and `locate(ref)` stay the navigator's.
- **`navigate(url)`**
  - It refuses, before anything is requested, a URL that isn't an absolute http(s) URL on an allowed origin. This is a policy event of the new kind `navigation` (`aqa_runner.document_origins.navigable_origin`).
  - It also refuses a URL with whitespace, a control character or a backslash anywhere. WHATWG URL parsing strips the first two and reads a backslash after an http(s) scheme as a slash, so the browser would read such a URL differently from Python's parser.
  - It never requires the current page to be allowed, so it is the way back after a policy event.
  - It checks the page it lands on, after any redirects, as every page is checked. A redirect to a subresource host passes the proxy and is refused here, as a `document` event.
  - A network failure raises Playwright's `Error` as it is. The egress gate's records tell an egress block (a redirect to a disallowed host is refused at the hop) from an infrastructure failure.
  - #46 joins a compiled path to the start origin first (the start URL amendment).
- **`reload()`** checks the page, reloads, and checks the page it lands on.
- **`resolve(target, use)`** checks the page before and after the lookup, and counts frame changes as `snapshot` does. Every result, an absence included, is an observation. A lookup run while the page went to another origin and back passes both page checks, so any frame navigation or removal during it discards the result, lets go of a resolved element, and raises `DocumentChangedError`. The caller looks again. A page that updates its history meanwhile has the same effect, and #46's settling comes first.
- **Actions** check the page and then the element's frame. An element in no frame is on none, so it is a `frame` event with an empty URL.
  - They also refuse an element when what a click on it lands in contains, at any depth, a frame on no allowed origin. The event is of kind `frame` and names that frame. "What a click lands in" is Playwright's click target: the closest button or link around the element, unless the element is a field (1.63's `retarget(node, "button-link")`). Containment climbs from the frame's element through both the DOM, shadow roots to their hosts, and the slots a node is assigned to, which Playwright's hit check follows (`expectHitTarget`).
  - Why: Playwright's hit check accepts the target or any descendant, and every point over a frame hits the frame's element. So a click on the page's root, on a region around a subresource host's frame, or on an allowed frame with one nested inside lands in that frame. The tests show an unchecked click on such a region reaching the frame. A frame slotted into a region of a shadow root, and one drawn over a paragraph inside a link, are reached the same way.
  - An element with another origin's frame drawn over it, but not inside it, is refused by Playwright's own hit check. Playwright 1.63 makes none, though, for an element in a frame whose element, or one around it, is transformed (`_checkFrameIsHitTarget`, `describeIFrameStyle`): the click lands in whatever is drawn at its point. `click` then refuses when the page has any frame off the allowed origins (the security re-review's proof clicked into one), and goes ahead when it has none.
- **`fill(element, value)`** never uses Playwright's own fill. That fill focuses the field, then inserts the text with the page's keyboard in a second protocol call, which goes to whichever frame has the focus by then. A subresource host's frame can take the focus programmatically and take it back whenever it loses it: the security review's proof received the whole value, with no policy event, and `fill_secret` (#49) would have sent it a secret.
  - The session fills in one script, in the element's own document: it selects what the field holds and inserts the text with `document.execCommand("insertText")`, which fires `input` (not `beforeinput` or key events, so an editor that acts only on those won't see it). The date-like kinds of `<input>` take the value as set, as Playwright's do. It then reads the value back, so a field whose page reformats what goes in (a mask) counts as not filled. `execCommand` acts on the selection of its own document whatever has the focus, so the text can't leave it.
  - A field that didn't take the value raises Playwright's `Error`, whose message never holds the value. The kinds of field match Playwright's: the text kinds of `<input>`, `<textarea>` and contenteditable elements.
- **`press(key)`** checks the frame where the key would go, asking only documents on allowed origins.
  - From the page down, it descends into the allowed child frame whose document has the focus (`document.hasFocus()`). Where none has, the key goes to the frame itself, unless that frame's focused element is a frame's element: then to that frame, which is on no allowed origin and is refused.
  - It also refuses when the focused element contains a frame on no allowed origin, since Tab would move the focus into it. The body and the document's root are exempt: they have the focus when nothing else has, and they contain every frame. A key goes to the focused element, never into a frame inside it, so this is the only way a key reaches such a frame.
  - *Why not `activeElement` alone:* Chromium can leave a document's `activeElement` on a frame that lost the focus to a sibling (LAB_NOTES, 2026-10-02). That reading wrongly refused typing into the app's own frame once a subresource host's frame had had the focus.
  - *Rejected:* asking each frame, the subresource host's included, whether it has the focus. That frame's own scripts answer.
  - When the focused element names an allowed frame that doesn't have the focus (a stale `activeElement`), where the key goes can't be told. `press` refuses if any frame on the page is off the allowed origins, and goes ahead if none is.
  - `key` is one key, with only Shift, Control, Alt, Meta or ControlOrMeta held before it, split as Playwright 1.63's press splits it (`press_keys`); anything else, an empty last key included (`Shift+`, which Playwright would leave held down), raises `ValueError`. In `Tab+a`, Tab held down moves the focus, perhaps into another origin's frame, and `a` follows it there unchecked.
- **Residual risk.**
  - The containment and focus checks run in allowed documents' own scripts' world, as the reach check does. The app's own scripts control that world, and so does a subresource host's script it loads.
  - `navigate` records a refused URL as given, query included. The error's message leaves it out, and redacting it before it is saved is #50's.
  - The app's own scripts could insert or navigate a frame between the check and the action. A subresource host's frame can take the focus on its own, so `press` checks where the key goes and then presses it, and that frame can try to win the gap between. `fill` doesn't depend on the focus.
  - Tab, or Shift+Tab, can move the focus from an allowed field into another origin's frame. That frame then gets the focus and the key's keyup; the next key is refused.
  - When Chromium leaves `activeElement` on a frame from another origin, `press` refuses keys meant for the frame itself. That fails closed.
  - Playwright's default action timeout (30 s) holds the session's lock while it waits. #46 sets its own.

## Amendment (2026-10-02): WebRTC's mDNS responder (#43)

The hostile-page suite's WebRTC page sent a packet past the egress proxy on Linux, though WebRTC gathered no candidate and sent no datagram: an IGMPv3 membership report, from the capture network's veth to 224.0.0.22.

- **Why.** A page that makes an `RTCPeerConnection` starts Chromium's WebRTC mDNS responder (feature `WebRtcHideLocalIpsWithMdns`, on by default), which hides local addresses in host candidates behind `.local` names. It starts with the peer connection, not with a candidate, and `disable_non_proxied_udp` (the amendment on the launch, above) doesn't govern it. Measured on the headless shell:
  - Linux, in the packet capture's network: Chromium binds UDP 224.0.0.251:5353 and joins 224.0.0.251 on the veth, and the kernel sends the join's report. No mDNS datagram followed.
  - macOS: `lsof`, without root, shows the network service holding UDP *:5353 on ten sockets, IPv4 and IPv6, one or more per interface. On a real host each join goes out to the local network.
  - The page chooses nothing in the report. But the browser announces itself on every network it's on, past the proxy, and listens there for mDNS while the peer connection lasts.
- **Decision (the maintainer's, 2026-10-02): turn the feature off at launch.** `aqa_runner.sandbox.DISABLED_FEATURES` lists the features every launch turns off, and `TRANSPORT_SWITCHES` passes them as one `--disable-features` switch.
  - *Why it repeats Playwright's list.* Playwright passes a `--disable-features` switch of its own first, and Chromium honours only the last: with Playwright's removed, a feature named only in the first of two switches stayed on (measured). So the launch's switch carries Playwright 1.63's fifteen features, then `WebRtcHideLocalIpsWithMdns`. This supersedes the amendment on the launch's *Not used: `--disable-features`*.
  - *A Playwright upgrade can't drop either.* `test_the_last_disabled_features_are_playwrights_and_webrtcs_mdns` reads the browser's real command line and requires exactly two such switches, the last being the first's list plus the mDNS feature. A Playwright release that changes its list fails it until `DISABLED_FEATURES` follows.
  - *What it costs.* Nothing measured: under `disable_non_proxied_udp` no ICE candidate is gathered with the feature on or off, with no ICE server and with STUN and TURN-TCP servers, on macOS and Linux. The SDP holds only `c=IN IP4 0.0.0.0`, and TURN-TCP still goes to the proxy, which refuses it. So the `.local` names had nothing to hide, and no local address shows without them, as long as `disable_non_proxied_udp` holds; the test below fails if a candidate is ever gathered.
- **Options.**
  1. One more switch, repeating Playwright's list (chosen): two edits, the sandbox module's constant and the command-line test's expected switches.
  2. `ignore_default_args` with Playwright's exact switch, then the merged one (rejected): the same merged list and the same drift test, plus a keyword in the `Chromium` protocol and in every test double. Playwright drops only an exact match, so after an upgrade it would quietly fall back to option 1's behaviour.
  3. Accept the join as a residual, and exempt IGMP from the hostile pages' packet check (rejected): the browser would still announce itself and listen on every network, and the check would no longer mean that nothing leaves except through the proxy.
  4. Remove `RTCPeerConnection` from sessions with an init script (rejected): apps under test that use WebRTC would break, and that is a product decision.
- **Tests.**
  - `tests/test_peer_connections.py`, through the packet capture (`tests/peer_connection_scenarios.py`): a session's page makes a peer connection with a data channel and an offer, gathers, then negotiates with a second one and adds remote candidates whose `.local` names it chose. Chromium resolves such a name: with the feature off it would ask the system resolver (mDNSResponder on macOS; on Linux glibc's name services: nss-mdns, resolved or plain DNS), with it on its own mDNS client, either way a query naming what the page chose (the security review's measurement, on macOS without the resolver rule). The launch's resolver rule fails the lookup before either; without it the capture holds DNS queries, one or more for each candidate (measured in an `ubuntu:24.04` container). On every OS gathering completes with no candidate and nothing holds a UDP socket on port 5353: on Linux no socket in the capture's network (`/proc/net`), where every socket is the scenario's; on macOS none of the session's Chromium processes (`lsof`). On Linux, nothing joined the mDNS group and the capture holds no packet but TCP. macOS's own mDNSResponder is in that group on every interface, so there joins can't be told apart. Red on main on both OSes: on Linux the socket, the join on the veth and the report; on macOS ten sockets on 5353.
  - `test_transports.py`: the command-line test expects the switch, and the drift test above.
- **Residual.** Proven on the headless shell only, as the launch's WebRTC switches are. Full Chromium (headed, as `PWDEBUG` forces, or by `channel`) reads the same switch, but nothing here runs it. After a Playwright upgrade that adds a feature to its list, that feature stays on until `DISABLED_FEATURES` follows, since the launch's switch wins; the drift test fails meanwhile.

## Amendment (2026-10-02): hostile pages (#43)

The Decision's egress tests: for each way a page might send data out, a hostile page in a real browser session tries it, and nothing reaches a disallowed host or leaves except through the egress proxy, observed at the packet level on Linux (the amendment on observing packets). This completes #43.

- **The suite.** `tests/test_hostile_pages.py` runs each method's page (`tests/hostile_pages.py`) through `observe`, in the scenario file `tests/hostile_scenarios.py`: a real `open_browser_session` behind the egress proxy, with an allowed origin on `127.0.0.1` that serves the page, a 307 `/redirect?to=` (which keeps a POST and its body) and the page's other scripts. The methods and their attempts:
  - fetch and XHR: straight to a canary, and through a redirect hop;
  - form POST: into a frame, straight and through a 307 hop;
  - WebSocket: from the page, from a dedicated worker, and as a `WebSocketStream`;
  - WebRTC: gathering with STUN and TURN over UDP and TURN over TCP; and remote candidates the page writes itself at address literals, UDP and TCP, IPv4 and IPv6, which a browser checks connectivity to with no server at all (the security review's addition). Remote candidates with `.local` names are `tests/test_peer_connections.py`'s (the amendment on WebRTC's mDNS responder), and candidates by any other name are looked up the same way: a DNS query without the resolver rule, none with it (measured on Linux);
  - QUIC: WebTransport, and HTTP/3 to an allowed https origin that answers `Alt-Svc: h3` naming a UDP canary;
  - IPv6 literals: `[::1]` and the IPv4-mapped `[::ffff:7f00:1]` (which reaches 127.0.0.1's canary), a redirect hop to `[::1]`, a worker's socket, and STUN;
  - DNS prefetch: `dns-prefetch` and `preconnect` by names only the proxy could resolve, and `preconnect` and `prefetch` to canaries;
  - service workers: registration plainly and through the prototype, of a worker script that would send to a canary;
  - non-HTTP schemes: `ftp:`, `gopher:`, a custom scheme (`aqa-exfil:`), `file:` (local and with a host) and `chrome:`, each by fetch, as a frame's source and by setting a frame's `location`.
- **Canaries.** Each attempt aims at a TCP or UDP listener of its own on `127.0.0.1` or `::1`, written as an address literal, which counts every connection or datagram. So each record names one attempt, and an attempt that got out to its canary would be heard on every OS. The by-name attempts have no canary: only the Linux capture could see them.
- **What every OS checks.**
  - No canary heard anything.
  - Routing's records and the gate's refusals are exactly the expected sets of distinct records: a missing record and an extra one both fail. Routing records an IPv4-mapped literal with no host, since no origin writes one (the amendment on routing).
  - Gathering completed with no candidate, so every attempt it makes was made; both registrations were refused with `SecurityError`, and the worker script was never asked for (by path, whatever its query); no frame ended on a document of another scheme, or on an http(s) origin the run doesn't allow; and the outcomes the page saw are pinned (requests failed, the routed socket closed, the worker's socket errored, the stream failed, every scheme's fetch failed).
  - Every connection an allowed origin accepted, whether or not a request followed, is one the egress proxy opened to that origin, and the proxy connected to allowed origins only (below). The https origin handshakes in the handler's thread, after the connection is recorded.
- **What only Linux checks:** every packet in the capture belongs to a TCP connection to the proxy's listener or to one the proxy opened. So no UDP (STUN, TURN, connectivity checks, QUIC, mDNS), no DNS (the prefetch names, secure DNS), no IGMP or ICMP, no IPv6, and no TCP to anything the proxy didn't open, to hosts no canary listens on included. macOS has no capture, so there the canaries, records and origin are the evidence (the amendment on observing packets).
- **Attribution.** Packets name addresses and ports, not processes, and in the capture's network a browser connecting straight to an allowed origin looks like the proxy's own upstream connection (that amendment's *Residual*). `AttributedGate`, a test subclass of `EgressGate` in the scenario file, calls the gate's own `connect` and records both ends of every upstream connection it opened. A packet is the proxy's when one of its ends is the proxy's listener, or when its two ends are one of those connections' (a port the proxy used, reused by another connection to another host, isn't). Each allowed origin records the peer of every connection it accepts; with that origin, each must be one of the proxy's connections. *The control*, `test_a_direct_connection_to_an_allowed_origin_is_caught`: the session loads the origin through the proxy, then a context with no proxy, in a browser launched without the launch-level proxy (`test_transports.WithoutTheSwitches`), loads the same origin straight. ## Amendment (2026-10-03): observation redaction (#50 A1)

### Context and options

A filled value is present in Playwright 1.63's raw [AI snapshot](https://playwright.dev/python/docs/api/class-page#page-aria-snapshot), and a page can reflect it through text, attributes and URLs. Scanning only at a later model or record writer leaves other callers exposed. Making every existing session caller supply a redactor would also change callers that bind no secrets. The boundary belongs on the session's observations, with a default empty scan and a mandatory fill interlock.

### Decision

- `Redactor` is constructed once from **all** `bound_secrets(...).values()`, including values no step fills. The executor passes it to `open_browser_session`; its existing fill-step subset still controls error withholding (until the #50 D amendment below). A1 does not change result, error or record presentation.
- `snapshot`, `visible_text`, `text_of` and `url` return `Redacted`, a `str` subclass only the redactor constructs. This records that a scan ran, not proof against arbitrary encodings or proof that another caller supplied this run's values. String operations, copies and pickle reconstruction return ordinary strings. `fill_secret` refuses an uncovered name or value with `ValueError` before filling; `NO_SECRETS` preserves callers that fill none.
- A scan replaces matches with `[SECRET:<name>]`, then applies any requested length limit. It matches raw values and arbitrary mixtures of raw and UTF-8 percent-encoded characters, plus for whitespace, in any case. Each character includes its full upper/lower/casefold forms. A separate whole-value default lowercase path preserves contextual final sigma before encoding (and, since the #53 ZW amendment below, each sigma spells all three). Whitespace uses JavaScript's set (U+FEFF included; U+0085 and U+001C–001F excluded); producers may trim ends and collapse runs.
- Base64 covers UTF-8 and, when encodable, Latin-1 (`btoa`), standard and URL-safe alphabets, padded/unpadded and then percent-encoded, at all three byte alignments inside larger data. A core holds only six-bit characters wholly determined by the secret; its adjoining partial characters and padding are consumed too. Cores shorter than four characters are not built. Values are therefore refused at binding (exit 12) if blank or shorter than four bytes after trimming in **either** supported encoding (or, since the #53 ZW amendment below, with under four bytes besides their gaps). The original accepted value remains unchanged for filling.
- Producer forms include JSON quoting and Unicode escapes (surrogate pairs included), YAML doubled apostrophes, C0/C1 hex escapes, Python's escaped UTF-8 bytes, and optional U+200B/U+00AD that Playwright removes (every gap, since the #53 ZW amendment below). These precede ref rewriting and any cut.
- Under the existing session lock: retire refs; check the page; take the raw snapshot; classify live frame origins using raw refs; check frame changes; prune entire forbidden raw subtrees; redact; rewrite ref imitations and renumber surviving refs. A final scan returns the marker type and only refs still present are published. Removed text is never rejoined. Pure parsing lives in `snapshot_refs`; document policy and state stay in `BrowserSession`. Scanning before subtree pruning is rejected because a value such as `ref=` destroys the syntax needed to exclude a forbidden frame (LAB_NOTES, 2026-10-03).

### Producer normalization order

Playwright removes U+200B and U+00AD before trimming and collapsing whitespace.
The scanner retains its original-value and whole-value lowercase paths, then
adds paths for the value with those characters removed and its whole-value
lowercase form (with every gap removed, since the #53 ZW amendment below). Existing tokenization now sees newly exposed edge whitespace
and joins newly adjacent interior whitespace runs before matching them.
Identical paths are deduplicated. Making only edge whitespace optional is
insufficient because removal can also join two interior runs into one.

Admission and filling still use the original value, as does base64 generation.
The added paths may match a short remnant in unrelated text, or positive-width
whitespace when the producer's fully normalized value is empty. This conservative
over-redaction is accepted. Empty paths cannot insert zero-width markers.
At most two additional paths survive deduplication per value; the work bounds
below include their token positions and spelling groups. No resource ceiling
is added. Base64 of a normalized value is outside this correction.

### Matcher correction

The scanner compiles finite spelling groups by consumed width. Standard-library regular expressions find those fixed-width spellings with simple Unicode case equivalence. Multi-character groups use lookahead so overlapping occurrences remain available. Only literal alternatives and fixed-width base64 character classes reach the regex engine. Tokens represent one, optional, zero-or-more or one-or-more occurrences.

For each observation, the scanner records every spelling endpoint and evaluates each token path backward. Each suffix table keeps the greatest reachable complete-match end at each input offset. Repetition follows only positive-width transitions to already evaluated later offsets. Equivalent histories share one state. Literal `%` and encoded `%25` endpoints both remain available until the whole path succeeds. Tables belong to the call and retain no observation afterward.

Selection starts at the leftmost unconsumed offset. At that offset, secrets retain descending original-value-length priority, stable in caller order for equal lengths. The chosen secret consumes its longest complete observed span across all paths. This explicit longest-span rule can redact more than legacy regex branch order. Consumed overlaps are skipped, adjacent matches remain eligible, inserted markers are not scanned again within the call, and zero-length matches are ignored. All-removable values therefore leave unrelated or empty text unchanged while their nonempty spellings still redact.

Rejected alternatives include deduplicating the composed regex, which leaves exponential ambiguity between optional or repeated spellings, and greedy atomic token choices, which can discard a valid whole-value match. A synchronous scan cannot be preempted by an asyncio timeout. A third-party regex timeout or killable process would add a dependency or lifecycle and a new failure contract. This correction adds neither.

Let `N` be input length, `P` the total token positions, `U` the distinct spelling groups, `A` the maximum finite alternatives or endpoints per token, and `W` the maximum spelling width. A conservative time bound is `O(N × P × A × W + N log N)`, plus emitted output. Sorting match starts contributes `N log N`. Materialized transitions and suffix tables use `O(N × U × A + N)` storage, plus compiled paths. Work does not multiply with the number of matching histories. No hard elapsed-time or memory ceiling is promised. The scan remains synchronous under the session lock and delays event-loop cancellation for its finite work.

### Consequences and limits

Every needle matches in any case, base64 in page text included: browser hosts are lowercased and CSS can transform reflected text. This accepts harmless over-redaction. The rough four-character case-insensitive core collision estimate is about one per two million positions (38⁻⁴), an approximation, not a measured benchmark. Short values are refused instead of accepting still smaller cores.

This remains SECURITY §5's best-effort reflection defense. Double percent encoding, base64 of percent encoding, other page-chosen encodings, Unicode normalization, locale-specific case mappings, truncated/fragmented values and pixels remain outside this scan. A2 owns result/error and recorded-URL redaction; later slices own saved evidence; screenshot masking is M2's (ADR-0033). #49's error withholding remains in force. There is no new dependency, paid resource or model call.

## Amendment (2026-10-05): recorded traffic and policy metadata (#50 A2)

### Context and options

Settle windows, policy events and popups keep the methods and URLs a page chose, and a replay result carries them in `StepResult.window` and `RunResult.policy_events`. A page can reflect a bound value into any of them (#49 B, #44, #46 C1). Network checks (ADR-0024's #48 amendment) compare exact methods and search complete URLs. ### Decision

- `Traffic` takes the session's redactor, built from every bound value. Each request is scanned once, when it starts, and its response's record reuses that scan. Its method is scanned in full. Its URL is scanned, then cut to `URL_CHARS` (2048), so the cut never leaves part of a value. Records hold plain `str`.
- `Traffic` keeps a private `Records[Exchange]` per window with the complete method, URL and status of the same responses: the first 100, every one counted, in window and response order. Nothing exported reaches the matcher.
- A policy decision reads the raw URL and origin. A policy event's URL and origin, and a popup's URL and opener, are scanned and cut the same way when recorded; `None` stays `None`. `PolicyEventError` holds the recorded event, so its message names the scanned origin.

### Consequences and limits

Complete metadata stays in process memory, private to `Traffic`: underscore privacy is no boundary against code in the same process. `network_held` answers a caller's regex over those complete URLs, so it must stay out of reach of model-facing tools and results: one question at a time, a model could read a reflected value back. Each kept response costs a second `Exchange`, whose complete URL is as long as Chromium allows. The scan covers the whole URL before the cut, with A1's lack of any time ceiling: with one bound value it measured 0.002 s for 2,048 characters and 2.5 s for 2 MB, so a page's long URLs cost the run time. A cut can keep a marker's prefix, and A1's over-redaction applies. A scan failure is not caught, and the scan has no failure a page can cause. Playwright 1.63 keeps it for its next protocol call. For a routed request, that call is the routing's continuation of the same request, which drops it, so the request stalls. A redirect hop isn't routed: it reaches the server unrecorded, and the error waits for the next protocol call (LAB_NOTES, 2026-10-05). `network_held` makes none, but replay's `evaluate` first looks at the page's visible text, a protocol call that would raise it, by Playwright 1.63's source (#277 measures this). *Amended by the #155 amendment below:* the failure now marks the session's traffic unrecorded on its way to Playwright, and every network check after it raises. Error reasons and infrastructure events are scanned by the amendment below; egress hosts and invariant texts stay slice D's; saved evidence is B's.

## Amendment (2026-10-04): explicit loopback connection ownership (#141, Unit A)

**Context.** A real socket accepted just before listener shutdown can outlive its server in CPython 3.14.7. Async transport construction then reaches `Server._attach` after `Server.close` has cleared the sockets. Construction fails before the caller receives the transport reference, leaving the accepted descriptor open before any application handler runs. Local handoff reproductions attributed this sequence independently to the proxy listener and `raw_upstream`. They do not identify the creators of historical #49/#51 warning reports. The upstream report is [CPython issue 109564](https://github.com/python/cpython/issues/109564).

**Decision.** Add `aqa_runner.loopback_server.LoopbackServer` as the shared internal ownership contract for a plain IPv4 listener at `127.0.0.1:0`. Unit A supplies this contract and its tests. Adopting it in the two attributed callers is the dependent Unit B change.

- The selector reader accepts synchronously and registers a connection before scheduling its task. Raw-socket ownership therefore exists even when cancellation prevents the coroutine from starting.
- Public [`loop.connect_accepted_socket`](https://docs.python.org/3.14/library/asyncio-eventloop.html#asyncio.loop.connect_accepted_socket) converts the accepted socket. `StreamReaderProtocol` synchronously records the writer and relinquishes raw ownership before conversion returns. After transfer, cleanup uses the writer/transport. Outgoing `asyncio.open_connection` substitution remains independent.
- Context exit removes the reader while its descriptor is valid, closes the listener, cancels unfinished handlers and joins their cleanup. The owner cancels each handler once itself, even while the handler's own timeout is cancelling it, so that timeout cannot turn shutdown into a `TimeoutError` the handler survives. A handler already in cleanup is joined without cancelling that cleanup. Each connection's own task closes its writer; no cleanup task is created. A caller's cancellation during exit waits for the join and is re-raised after it, so it cannot abandon a transferred connection. A queued callback on a retired listener cannot accept again. Partial entry/setup and task-submission failures release their allocated resources; a stream that fails before recording its writer is closed through the transport that conversion returned. Entry failures propagate from entry.
- Cleanup waits for the transport's own loss, not only `StreamWriter.wait_closed`. A handler cancelled while awaiting `wait_closed` cancels the stream's shared waiter, which then proves nothing about queued output or the descriptor. A small public `asyncio.Protocol` delegate forwards the six stream callbacks to the ordinary `StreamReaderProtocol` and sets an owner-held Event after `connection_lost`; it is built inside the accepted socket's rollback. Queued output drains before exit returns. A peer that never reads keeps exit pending, as `wait_closed` would; no deadline or abort is added.
- Would-block, interruption and an aborted queued connection are transient accept outcomes. Other accept errors, including resource exhaustion, retire the listener and cancel its connections. There is no retry timer. The run loses this listener after failure, which avoids repeatedly dispatching a readable descriptor that cannot accept.
- Unexpected task failures are retrieved and reported once through the loop exception handler, including failures during shutdown. Completed connection records are released promptly. Distinct cleanup and handler failures produce separate reports. Expected connection-close errors, shutdown cancellation and a cancelled shared close waiter do not become unexpected failures. A context-body exception retains its identity; handler failures do not newly propagate from context exit. Unexpected synchronous callback errors retire the listener before reaching the loop's callback-error channel.
- This contract targets the default CPython selector loops on Linux and macOS. It adds no SSL listener, alternate event-loop or custom task-factory support. Upgrading an owned writer with `start_tls` is unsupported: it replaces the close-notice delegate, so exit would wait forever. It neither interprets request bytes nor changes origin policy or outbound dialing.

**Alternatives.** Handler-only cleanup cannot reach the observed pre-handler failure. An arbitrary delay before shutdown has no ownership proof. Patching private asyncio internals or changing the global task factory affects unrelated users. A fixed released interpreter would be preferable to local ownership code if it demonstrably removes the mechanism; the bounded comparison of 3.14.8's five relevant methods with 3.14.7 found unchanged source, without installing or executing 3.14.8. The proposed upstream correction is [CPython PR 154861](https://github.com/python/cpython/pull/154861). For closure, only silencing the cancelled waiter's report left queued output and an open descriptor after exit (measured); a static `StreamReaderProtocol` subclass bypasses construction-time protocol observation; aborting queued output or a cleanup deadline would change delivery; reading the stream's private close future, polling, and a spawned cleanup task were rejected.

**Consequences and verification.** The internal owner adds lifecycle code and failure tests but no dependency, tenant surface, paid resource or model call. Tests assert real accepted-descriptor and peer closure before test cleanup, cancellation after actual transport allocation but before adapter return, compatibility with a host/port-only outgoing mock, partial registration failure, persistent callback retirement, coroutine/task cleanup, error-channel behavior during active handling, shutdown and a body exception, caller cancellation during exit, cleanup without a new task, a cancelled close waiter with and without queued output, a paused peer's drain, and close-notice allocation failure. Unit A leaves the existing caller lifecycle behavior in place until Unit B. macOS runtime and Linux type analysis are separate evidence from Linux runtime checks.

**Decision.** `EgressProxy` serves on `LoopbackServer` instead of `asyncio.start_server`. ## Amendment (2026-10-08): per-phase listeners, uncertain traffic and a retired listener (#53 P8, #162)

**Context.** Explore resets the app between its attempt and its confirmation (ADR-0024). A reset is safe only once the attempt's traffic has stopped: a connection still queued, paused in stream conversion or mid-exchange when the browser closes can reach the app after the reset. Separately, #141 Unit B's loopback owner retires its listener on a persistent accept error (R2: no retry), and the failure reached only the loop's exception handler, so a replay whose browser could no longer reach the proxy reported the app's failures instead of an infrastructure error (#162). And replay read its verdict inside the browser session, so a block or an event recorded as the browser closed never reached it.

**Decision.**
- *Phases.* `EgressProxy` opens with its first phase. `end_phase()` stops the phase's listener, so a queued connection is never accepted, cancels and joins every accepted connection, one paused in stream conversion included, and returns `PhaseTraffic`. `begin_phase()` opens the next listener on a new port. A connection counts in the phase whose listener accepted it. A phase stays the proxy's until its join is done: `begin_phase` refuses while one is open or ending, `url` raises between phases, and a caller's cancellation of `end_phase` waits for the join, as does closing the proxy while another task ends its phase. One gate, policy and block record still span the run.
- *Uncertain traffic.* A plain exchange that sent any byte upstream, noted before it goes so a partial send counts, without its response reaching the browser through its end is uncertain. So is any tunnel that carried a byte upstream, however it ended: the proxy never sees inside one. Refused, unconnected and unreadable requests, and tunnels that carried nothing, are clean. Explore resets only after a phase ends with nothing uncertain, so in M1 a phase whose traffic used HTTPS or a WebSocket exits 14 (API.md §7).
- *A retired listener (#162).* `LoopbackServer(handler, on_retired=...)` calls back once when an accept error retires the listener, after it has stopped and before the loop's exception handler hears of it. A transient error retires nothing. The proxy records `InfrastructureEvent("127.0.0.1", <the phase's port>, "the egress proxy stopped accepting the browser's connections after an accept error (EMFILE)")` in the run's gate: fixed text and the errno's name, or the error's class. The event outlives the phase, whatever its traffic, and `url` raises once the listener has retired, so no browser is launched toward a port another process could take. R2 stands: nothing reopens the listener.
- *Replay's verdict.* Replay ends the proxy's open phase once its browser has closed, then reads the run's egress blocks, infrastructure events and outcome. A block or an event recorded while the browser closes, or while the phase's connections are joined, makes the run errored. The proxy is between phases when replay returns, and its callers close it as before.

**Rejected.** A grace wait (`quiesce`) on one listener shared by every phase: with the browser closed, no open exchange can complete, so waiting changes nothing, and a shared listener ties a later phase to draining an earlier one. Re-reading only `errored` after the session: it misses blocks and anything recorded while the phase's connections are joined (`test_executor_runs.py`).

**Consequences.** Every one-phase user is unchanged, except that replay leaves the proxy between phases. `test_egress_phases.py` covers classification, the queued, paused and released connections, transitions under cancellation and `KeyboardInterrupt`, and the retired-listener event; `test_loopback_retirement.py` the owner's callback; `test_executor_runs.py` EMFILE after the first navigation and the teardown regressions.

## Amendment (2026-10-14): a bound value split by gaps (#53 ZW, #195)

### Context and options

Playwright 1.63's AI snapshot drops U+200B and U+00AD from text, as A1's producer normalization says, but keeps every other default-ignorable code point (U+200D, U+2060 and U+FE00, say) and every private-use one, in text, accessible names, field values and `/url:`. A page could split a bound value with one, and the scan, which knew U+200B and U+00AD only inside a value holding them, let the value reach the model: in a snapshot, in a field the page filled from the secret and split, in a `RefError` that quotes a model's ref with Python's `repr`, past `Redactor.spells` and the journal check, and in the navigator's request.

Options for the match: a second pass over the text with gaps removed and spans mapped back, which is slower than the scan it adds to and blind to escaped gaps (`%E2%80%8D`, `\u200d`); or gap-tolerant units in the existing token automaton (chosen). Options for escaped gaps: every gap's escapes listed as regex alternatives from a trie over the set, an import cost that grows with the set; or a few fixed escape shapes whose matches are decoded and kept when they are one gap (chosen).

### Decision

- **The gap set** is `aqa_runner.redaction.GAP`: one character of Unicode 16's Default_Ignorable_Code_Point or of the private-use areas (U+E000 to U+F8FF, U+F0000 to U+FFFFD, U+100000 to U+10FFFD; the maintainer, 2026-10-14), 20 ranges. A test pins it equal to the shipped Chromium's `/[\p{Default_Ignorable_Code_Point}\p{Co}]/u` over every code point. It has one meaning in the scan: a gap may come before a unit of a value, a value's own gaps are optional, and admission ignores gaps. A consumer that needs the set imports it from `redaction` (from `bound_secrets` until #215).
- **Gapped units.** Every token of a path after its first takes a run of gaps before each of its units: between a value's characters, inside a whitespace run, inside a case expansion, and before base64's partial characters, core and padding. A match starts and ends on a unit, so gaps around a value stay and only the value's span is replaced, with no span map.
- **Escaped gaps.** A gap counts in each spelling the scan finds a value's own characters in, and in those Python's `repr` writes: UTF-8 bytes percent-encoded or written `\x`, JSON's `\u` and its surrogate pairs, and `repr`'s `\x`, `\u` and `\U`. Five fixed shapes are matched case-insensitively, and each match is decoded in Python and kept only when it is one character of `GAP`, so the private-use areas' 137,468 code points add no table.
- **Paths.** The value, its whole-value lowercase and its casefold, each as written and with its gaps removed. The casefold path writes each character of an expansion (ß as ss) as a unit a gap can split. A value's own gap is optional where it stands, and a whitespace run made only of its own gaps (U+FEFF, which is JavaScript whitespace) is optional on its own, so a value holding several is found with any of them left out. Each sigma in a value spells all three sigmas: whether Σ lowercases to the final sigma depends on what follows it, which a page changes with a gap that Unicode doesn't count as case-ignorable (a private-use character, a Hangul filler) or by leaving out one of the value's own gaps, and percent-encoding and JSON write the final sigma apart from the other. This replaces A1's optional U+200B and U+00AD and the paths its "Producer normalization order" adds, which are the case where those two are the gaps.
- **Every scan inherits it.** Model-bound and saved text goes through `Redactor` (`redact`, `finds`, `spells`, `markers_spell_a_value`), so snapshots, `text_of`, `visible_text` and `url`, the navigator's request blocks, `error_text` and `reasons.reason`, the navigator tools' argument checks, `require_clean` and saved evidence, and recorded URLs and console text find a split value with no caller change.
- **Consumer rule.** A consumer that transforms page text before the model reads it, removing gaps say, scans the text as written, transforms it, then scans the result, and the model reads only that last scan.
- **Admission.** `bound_secrets` also refuses, before any browser, in explore, replay and the pilot (exit 12, API.md §7), a value with under 4 bytes in UTF-8 or, when encodable, Latin-1 once its gaps are removed and the rest is trimmed of JavaScript whitespace: "AQA_SECRET_<NAME> must have at least 4 bytes without Unicode's default-ignorable and private-use characters in UTF-8 and, when encodable, Latin-1, since a page can leave them out". Without it, four U+200D and `a` would replace every `a` on a page. The maintainer approved the refusal and that it counts private-use characters (2026-10-14).
- **A1's matcher, widened.** Besides literal alternatives and fixed-width base64 classes, the gap class (20 ranges) and the five escape shapes now reach the regex engine, and their matches are decoded in Python. A `Redactor` numbers each distinct tail of its paths once, a token and the tail after it, so paths that share a tail (base64's partial and padding, a value's case forms) share its number; a scan computes each tail's table once, from the longest tail it still holds, and drops it after its last read.

### Consequences and limits

- **Cost**, measured at `4c7b186` against main `a0279e2`: `Redactor.redact`'s median of 5 runs per input, main and the branch interleaved over two rounds, with one and with three bound values, on Conduit's pilot snapshots, a 100,000-character listing, journal and URL, URLs of 2,048 and 2,000,000 characters, 100,000 characters of U+200D and `a` and of its percent-encoding and `a`, and 96,000 of split values. The branch took 0.43 to 0.87 of main's time on these 17 inputs, and 0.57 to 0.92 on 100,000 characters of a private-use character and `a` or of its JSON escape and `a`. The worst ratio is the input that is half gaps. The 2,000,000-character URL took 2.4 s against main's 3.6 s, so #154's bound on long URLs stays open. Importing `redaction` took 0.0046 to 0.0048 s against main's 0.0028 to 0.0032 s. Peak memory of one scan (`tracemalloc`, the same two commits): 1,158 MB against main's 1,038 MB on the 2,000,000-character URL, 63 against 55 MB on the 100,000-character URL with three values, and 68 against 60 MB for a value of 128 `a`s over 100,000 `a`s, which a memo that kept every table to the end of the scan had taken to 713 MB.
- **Over-redaction.** A near-copy of a value with gaps inside is replaced, as is the value with its own gaps left out or with one sigma written for another. The admission bound is not the shortest text a value replaces: it removes gaps and trims the ends, but the scan also collapses interior whitespace runs, so an admitted `a`, U+200D, four spaces, U+200D, `b` replaces the three bytes `a b`. A value with an interior whitespace run already did so before this amendment (`a    b` replaces `a b`); like A1's whitespace over-redaction, this is accepted.
- **Not found** (residuals): a value a page splits with U+FEFF, which Playwright writes as a space, a visible character; a value with two or more case-expanding characters, one written expanded and split by a gap and another not; another Unicode normalization form (NFC, NFD, NFKC); homoglyphs; base64 of a split value, since base64 is built from the value as given; a value's own gap at either end written as Python's `repr` writes it (`\xad`, `\U000f0041`), which stays beside the marker, though no producer today writes a bound value that way before a scan.
- Tests: `packages/runner/tests/test_invisible_splits.py` (raw, percent, JSON, `\x` bytes and `repr` at the first and last code point of each range; snapshots and a reflected field in real Chromium; tool errors; requests; part-line-shaped text; the journal check and saved evidence; base64 at each alignment; case expansions; a final sigma a gap makes; whitespace runs and own gaps at a value's ends; each U+FEFF on its own; the set against Chromium's), and `packages/runner/tests/test_bound_secrets.py` (admission). No dependency, paid resource or model call.

## Amendment (2026-10-18): explore's output boundary and its browser driver (#53 P17)

### Context and options

The CLI assembles its own text after the runner's scans: the outcome and the spec id, the time and cost, paths, indentation, the warning, each reason. A join of clean parts can spell a bound value, and so can escaping or a printed path (Codex's plan review F1). A marker can spell its own value when the value is inside the secret's name, so no scan takes it out (`redaction.py`), and a runner refusal can be about exactly that binding (Codex's delta review N1). The CLI also starts Playwright's driver itself, which can fail before the run begins, and must stop it however the command ends (F2, N2, N7, N9, N11; maintainer, session 18: exit 13).

### Decision

- **One output boundary that fails closed** (`aqa_cli.explore._rendered`, which `_say` writes). Every line `aqa_cli.explore` writes goes through it. Each line is scanned whole with the run's scan, so a join a line holds is found; then escaped (`_visible`), joined, and scanned whole again, since escaping or a line break can spell a value too, as `redaction.error_text` does: two scans, never a loop. If the result still spells a value (`Redactor.finds`), none of it is written. The caller's fixed fallback lines are written instead, each escaped before it is checked, so what is checked is what `typer.echo` gets: Click strips ANSI codes from a stream that isn't a terminal after any check of ours, and a terminal obeys them. A fallback line that spells a value is left out. When the kept lines' join spells one, only the last is written: the caller's status line, `non-resumable`, which callers put last. A run's line and the lines after it (`_said`) are rendered before either stream is written, and on exit 0, when stdout gets the line and stderr the rest, their join as a merged log (`2>&1`) reads it is checked too: stdout's text, the line break `typer.echo` adds, then stderr's. When the join spells a value, each stream writes its fallback instead, and stderr nothing when the two fallbacks' join spells one (Codex's adversarial review of #53 P17, C2; maintainer, session 19). The exit code stands, whatever was written.
  - *Where the fallback's words come from:* `<outcome> <spec id>: the rest is withheld, since it would spell a bound value`, a constant of the CLI formatted with the outcome word and the spec id only, and the fixed word `non-resumable`. No page, model, run, path or OS text enters it. The spec id is the spec's file name, which may hold any character, controls included; that is why each line is escaped before its check. The scan reads a gap (a bidi control) written or escaped, so a spec id with one inside a value's spelling still spells it once escaped, and that line is left out.
  - *The scan.* The CLI binds once itself, `Redactor(bound_secrets(spec, start).values())` after the provider's key, as `explore` does first, rather than taking the run's redactor from `Explored`: a refusal that raises returns no `Explored`. The two reads agree while the environment's bindings are stable through the run (the #53 P16b amendment's assumption; a test proves them equal for one invocation). The scan is empty in three places, each for its own reason: usage, the spec and the budgets, before any binding exists; `--plan-only`, which binds no test secret and whose request leaves out the account and the reset hook; and a compiled script kept up to date, with no run at all.
- **Exit 13 for a driver that can't start** (maintainer, session 18). `_explored` creates the start's task, `asyncio.create_task(async_playwright().start())`; `_driver` reads its outcome as a value (`asyncio.gather(..., return_exceptions=True)`) while it holds the loop's exception reports. An `OSError` (the spawn), Playwright's `Error` (the handshake), or exactly `Exception("Connection closed while reading from the driver")` (Playwright 1.63's words when its driver exits before the handshake, matched by type and arguments, since it has no class of its own) is `unreachable <spec id>: the browser driver couldn't start, so nothing was explored`; the CLI adds no OS error and no traceback, though a driver that fails may print its own diagnostics first (below, not covered). Reports holding that error are dropped (Playwright leaves a failed spawn's error in a task nobody reads, which asyncio would log, path and all); every other report is passed on, and the handler restored. Any other failure goes on as it came.
- **A driver the start returned is always stopped.** `_explored` holds the start's task from its creation to its `finally`. There, a start still pending is cancelled and joined (`asyncio.wait`), with no await between the `done()` test and the cancel; a start already done is read at once, since `asyncio.wait` on a done task still yields, and a first cancellation landing there skipped the stop (Codex's delta review N11). A task neither cancelled nor holding an exception produced a driver, which is stopped once; a stop that fails (`OSError`, Playwright's `Error`) changes nothing, so the result, or the error in flight, wins.
- **The listener's own error is the only listener mapping** (maintainer, session 18). `ListenerUnavailableError` (the #53 P16b amendment), from the attempt's phase or the confirmation's, is `unreachable <spec id>: the egress listener couldn't start, so nothing was explored` (13); the plan's cost lines stay in the record. Every other exception, every other `OSError` included, propagates: exit 1 with Typer's traceback and no locals. That is the contract for unexpected failures.

### Consequences and limits

- *Not covered by the boundary:* Typer's own usage and help text, before any binding; a bug's traceback (exit 1); two writers that share the CLI's stderr: Playwright's driver, a child process Playwright 1.63 starts with the CLI's own stderr and no option to change it (`_transport.py`), whose own diagnostics (Node's, when it can't start, or what an environment such as `NODE_OPTIONS` makes it print) reach the terminal unscanned, and the reports of an error nobody read (Playwright's listener errors, and asyncio's default handler once `_driver` restores it), a bug like a traceback (from #53 P17's reviews; a bound value placed where the driver could print it is refused at binding since #215, and that amendment lists what stays open); a reader that shows stderr's text before stdout's, as one reading the two pipes apart may: only the order the CLI writes, stdout's then stderr's, is checked (#53 P17's security review of the C2 fix); and what the stream's encoding does after `typer.echo`, which writes a character it can't hold escaped, replaced or as its raw byte. On a UTF-8 stream the only such characters are lone surrogates, which only a file name that isn't UTF-8 puts in a printed path.
- *The driver's residuals.* (1) A Playwright version that changes the early-exit words; a test pins them, so an upgrade fails there first. (2) A second Ctrl-C while the cleanup awaits a pending start's join or the stop interrupts that cleanup; there is no completion guarantee for a second interrupt. (3) A start that fails or is cancelled mid-handshake raises out of Playwright's `__aenter__` with no driver object to stop; its connection task is left to `asyncio.run`'s shutdown and its driver process to garbage collection or the CLI's exit, which closes the driver's pipes (measured for a failed handshake with the real driver in #53 P17's security review: the process outlives `asyncio.run`, and Python reports its transport unclosed). (4) A first cancellation delivered while the stop itself awaits, after Playwright closed the driver's input: the cancellation goes on instead of the result or the error in flight, and the wait for the driver's exit is left to `asyncio.run`'s shutdown. Publication and the record's writes happen before `explore` returns, so only the printed line is lost.
- No dependency, paid resource or model call. Tests: `packages/cli/tests/test_explore_output.py` (each scan, the fallback and its escaping, the status line kept, the two streams' join, the egress record line) and `test_explore_driver.py` (Playwright's real driver failing to spawn or exiting early, in process and in a child; stand-ins for a failed handshake, held reports, a cancellation while starting, a start never read, a cancellation queued as the run ends, the listener's error and other `OSError`s).

## Amendment (2026-10-18): a session that can't be prepared, and cleanup once the driver has gone (#204)

- **A session that can't be prepared exits 10.** `open_browser_session` is now the composition of `launched_browser` (the launch and the sandbox check, which own the browser's close) and `prepared_session` (the context with the phase's proxy, the init script, routing, the page and the observers), in that order. A Playwright `Error` as the session is prepared, Chromium exiting right after its check included, becomes `SandboxUnavailableError("Chromium's session couldn't be prepared after its sandbox check (<class>)")` from the original. The words are fixed and name Playwright's class only, with no host fix, since the check proved the sandbox. For a Playwright `Error`, this supersedes the 2026-10-07 amendment's "Context setup, routing, the caller's body and cleanup keep their own errors"; any other setup failure keeps its type.
- **Cleanup once the driver has gone.** Playwright 1.63 starts its node driver in the runner's process group, so a terminal's Ctrl-C kills it too, and every later call fails. On these paths a context and the check's CDP session are cleaned up on normal ends only; otherwise the browser's close takes them. That close, in `launched_browser` and on the sandbox check's failure path, is `sandbox.close_while_raising`: while an error or a cancellation propagates, it leaves to it a close failing with exactly `type(e) is Exception and e.args == DRIVER_GONE` (`("Browser.close: Connection closed while reading from the driver",)`, `_impl/_transport.py:166` as `wrap_api_call` names it). A close after a normal end still raises. The match is narrow by design (Codex's #53 P18 plan review F2), as P17's D8 matches the driver's early exit.
- **What it never swallows:** the same failure after a normal end; a Playwright `Error` of any subclass with those words; any other words; a `BaseException` from the close (a second Ctrl-C, a cancellation, the deadline); another call's driver-gone error, which is the error in flight and propagates; a setup failure that isn't a Playwright `Error`.
- **The phase ends once no context names its port, on every path** (the #53 P8 and #162 amendment's "Replay's verdict" order; this narrows the #53 P16a amendment's "replay ends its phase on every exit"). Ending a phase stops its listener and frees its port, so no live context may still name that port as its proxy: another local process could bind it and receive allowed-origin requests, bodies included (LAB_NOTES, 2026-10-20). Replay with a browser of its own closes it, then ends the phase, as before. With a browser its caller launched, explore's confirmation, replay ends the phase on a return, once the session's context, the only one naming the phase's proxy, has closed. On a raise that context is still live, so replay leaves the end to its caller, which ends it once the browser has closed, outside explore's budget span (ADR-0024's #204 amendment). There, the proxy is between phases once the caller has ended it, not when replay raises. Rejected: replay closing its caller's browser before the end, which puts the close back inside the budget's span, and closing the context on the raise, which needs a second driver-gone match and also runs inside the span. Follow-up: keep an ended listener's port bound until the proxy closes.
- **Rejected:** starting the driver in its own session, for which Playwright 1.63 has no option.
- **Residuals.** New words from Playwright fail the Ctrl-C test, and until the match follows, a Ctrl-C exits 1 again. A call that fails with the driver-gone error before the cancellation arrives propagates that error. The sandbox check's own refusal closes its browser inside `launch()`, inside explore's budget span. A driver whose Chromium was killed ignores SIGINT (measured on #204's plan sketch).
- Tests: `packages/runner/tests/test_session_failures.py` (the conversion, a kept error or cancellation, the check's cleanup, a normal end that raises, the narrow match, the context's close), `test_explore_stops.py` and `test_replay_phases.py` (exit 10, Ctrl-C mid-turn as `KeyboardInterrupt`, and the phase ending after the browser's close), in real Chromium with the driver interrupted by SIGINT.

## Amendment (2026-10-27): a bound value elsewhere in the environment (#215)

### Context and options

Playwright 1.63 starts its node driver with a copy of the runner's environment (`_impl/_driver.py`, `get_driver_env`) and with the CLI's own stderr (`_transport.py`), so the driver's own diagnostics reach the terminal or the CI log unscanned (the #53 P17 amendment, "Not covered"). Measured: with `NODE_OPTIONS="--require /nonexistent/<value>/x.js"`, Playwright's node prints `Error: Cannot find module '/nonexistent/<value>/x.js'`. The environment is the operator's or the CI job's, not the spec author's, so the threat is a value placed by accident: a secret exported under a second name too, or written into a proxy URL, a path or a preload. Nobody can list every variable that node, Playwright or a Python library echoes, so the check fails closed. Rejected: an exact substring match, which misses a percent-encoded proxy password or a base64 basic-auth value that node prints as written; a new exception class, which every caller would have to catch, a missed one exiting 1; and exempting each value only in its own `AQA_SECRET_<NAME>`, as #215 is worded, which refuses two test accounts that share a password and protects nothing more, since the driver inherits every `AQA_SECRET_*` variable anyway (coordinator decision).

### Decision

- **The refusal.** Once every value is read, `bound_secrets` raises `SecretLoggedError` (exit 12) when any variable outside `AQA_SECRET_*` spells a bound value in its name or its value, by `Redactor.spells`: any case, percent and base64 at every alignment, JSON-escaped, producer quoting, gaps. Both entry points bind before they start Playwright's driver: `aqa explore` (`aqa_cli.explore`, before `_explored`) and the bench's replay (`pilot_replay._check_secrets`), so the run stops with no driver, no browser and no intent written. The runner's `explore` and the executor's admission bind again with a driver already started, so `aqa replay` (#239) must bind before it starts one.
- **The message** names every such variable, sorted. No scan reads it (the CLI's scan is still empty when `bound_secrets` raises), so a variable whose name spells a value is written as `a variable whose name holds one`.
- **Any `AQA_SECRET_*` variable may hold any bound value.**
- `VALUE_WHITESPACE` and `GAP` move to `aqa_runner.redaction`, so `bound_secrets` imports `Redactor` without a cycle.

### Consequences and limits

- *Not covered:* (1) the driver still inherits `AQA_SECRET_*` itself, so an environment that makes node print its own environment (a preload that logs `process.env`, `--report-on-fatalerror`) still prints the value; Playwright 1.63 has no option for the driver's environment, and popping the variables after binding would break the CLI's second binding (the #53 P16b assumption). A follow-up could run the driver without them. (2) Anything printed before binding: Python's own startup (`PYTHONWARNINGS`, `PYTHONSTARTUP`), import-time warnings, the provider router. (3) Spellings the matcher misses (SECURITY §5): double encoding, Unicode normalization, a value split across two variables. (4) An environment changed after binding, and the content of a file a variable points at, such as a preload that prints the value. (5) Hosted runs, which take values from the `test_secrets` API (M5). (6) The refusal's own words: a value that is one of them (`driver`, say) shows in it, as in every exit-12 message, since the CLI prints them unscanned.
- *False positives.* The scan matches a value in any case, and a value can be 4 bytes, so a short or common-word value collides with unrelated text: `CI=true` and `CHROMEWEBDRIVER` on GitHub's runners, `COLORTERM=truecolor`, pytest's `PYTEST_CURRENT_TEST`. The refusal names the variable, so the user can act. Tests that bind a common word, or whose id spells their value, take `secret_fixtures.hermetic_environment` (LAB_NOTES, 2026-10-27).
- One scan of the environment per binding. No dependency, paid resource or model call. Tests: `packages/runner/tests/test_bound_secrets.py` (each spelling, every variable named at once, a name that holds a value, a value shared between `AQA_SECRET_*` variables) and `packages/cli/tests/test_explore_console_script.py` (the `NODE_OPTIONS` reproduction exits 12 before the driver starts).
